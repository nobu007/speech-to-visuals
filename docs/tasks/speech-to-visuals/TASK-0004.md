## 実装詳細

### 1. audio バケット作成 🔵

**信頼性**: 🔵 *database-schema.sql ストレージセクション・architecture.md データベース構成より*

`audio` という名前のストレージバケットを作成する。

設定:
- バケット名: `audio`
- 公開アクセス: `true`（読み取りは公開、書き込みは認証済みのみ）
- ファイルサイズ制限: 50MB（REQ-402 に準拠）
- 許可MIMEタイプ: `audio/mpeg`, `audio/wav`, `audio/ogg`, `audio/x-m4a`

**実装ファイル**: `supabase/migrations/00002_create_audio_bucket.sql`

### 2. 読み取りポリシー設定 🔵

**信頼性**: 🔵 *database-schema.sql・NFR-102・architecture.md Supabase構成より*

`audio` バケットに対する読み取りポリシーを設定する。

- **ポリシー名**: `audio_bucket_public_read`
- **操作**: SELECT
- **対象**: 全ユーザー（匿名含む）
- **条件**: バケット内の全オブジェクトを参照可能

**実装ファイル**: `supabase/migrations/00002_create_audio_bucket.sql`

### 3. 書き込みポリシー設定 🔵

**信頼性**: 🔵 *database-schema.sql・NFR-102より*

認証済みユーザーによる書き込みポリシーを設定する。

- **ポリシー名**: `audio_bucket_authenticated_insert`
- **操作**: INSERT
- **対象**: 認証済みユーザー（`auth.role() = 'authenticated'`）
- **条件**: ユーザーは自分のフォルダ（`{user_id}/`）にのみ書き込み可能

**実装ファイル**: `supabase/migrations/00002_create_audio_bucket.sql`

### 4. 削除ポリシー設定 🔵

**信頼性**: 🔵 *database-schema.sql・NFR-102より*

認証済みユーザーによる削除ポリシーを設定する。

- **ポリシー名**: `audio_bucket_authenticated_delete`
- **操作**: DELETE
- **対象**: 認証済みユーザー（`auth.role() = 'authenticated'`）
- **条件**: ユーザーは自分のフォルダ（`{user_id}/`）のファイルのみ削除可能

**実装ファイル**: `supabase/migrations/00002_create_audio_bucket.sql`

### 5. ストレージポリシー検証SQL 🔵

**信頼性**: 🔵 *NFR-102・database-schema.sqlより*

ストレージポリシーが正しく機能することを確認する検証SQLスクリプトを作成する。

- バケット存在確認: `storage.buckets` のクエリ
- ポリシー一覧確認: `storage.objects` に関連するポリシーの確認
- ファイルパス制限確認: ユーザーフォルダ分離のテスト

**実装ファイル**: `supabase/migrations/verify_storage_policies.sql`

## 単体テスト要件

### テストケース1: バケット作成確認 🔵

**Given**: マイグレーションが適用済み
**When**: `SELECT * FROM storage.buckets WHERE id = 'audio'` を実行する
**Then**: `audio` バケットが存在し、`public` が `true` に設定されている

**テストファイル**: `supabase/migrations/verify_storage_policies.sql`

### テストケース2: 読み取りポリシー確認 🔵

**Given**: audio バケットが存在する
**When**: 匿名ユーザーが audio バケットのファイルを参照する
**Then**: 公開読み取りポリシーによりファイルのURLにアクセス可能である

**テストファイル**: `supabase/migrations/verify_storage_policies.sql`

### テストケース3: 書き込み権限確認 🔵

**Given**: audio バケットが存在する
**When**: 認証済みユーザーが自分のフォルダにファイルをアップロードする
**Then**: アップロードが成功する

**When**: 認証済みユーザーが他ユーザーのフォルダにファイルをアップロードする
**Then**: アクセスが拒否される

**テストファイル**: `supabase/migrations/verify_storage_policies.sql`

### テストケース4: ファイルサイズ制限確認 🔵

**Given**: audio バケットに50MB制限が設定されている
**When**: 50MBを超えるファイルをアップロードする
**Then**: アップロードが拒否される

**テストファイル**: `supabase/migrations/verify_storage_policies.sql`

## 統合テスト要件

### 統合テスト1: Supabase クライアント経由のアップロード・ダウンロード確認 🔵

**テスト内容**: Supabase JS クライアントを使用して、認証済みユーザーが音声ファイル（MP3）をアップロードし、公開URLからダウンロードできることを確認

**テスト内容**: 異なる2人の認証ユーザーでファイルのアップロード・削除を行い、他ユーザーのファイルにはアクセスできないことを確認
**期待結果**: 各ユーザーは自分のフォルダ内のファイルのみ操作可能

## 注意事項

- ファイルパスは `{user_id}/{filename}` の形式とし、ユーザー間のデータ分離を確保すること
- MIME タイプ検証は Supabase Storage の制限により完全ではないため、アプリケーション層でもバリデーションを行うこと
- 公開読み取りは音声ファイルの再生用URLの生成に必要。ただし、機密データは含まれない前提
- 50MB 制限は REQ-402 に準拠。Supabase Storage のデフォルト制限との整合性に注意
- マイグレーションファイルは TASK-0003 のマイグレーションとは別ファイルとすること
