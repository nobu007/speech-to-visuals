## 実装詳細

### 1. レスポンシブレイアウト基盤実装 🟡

**信頼性**: 🟡 *architecture.mdから妥当な推測*

Tailwind CSSのレスポンシブクラスを使用したレイアウト基盤の実装。全コンポーネントで一貫したブレークポイント戦略を適用する。

- ブレークポイント定義（Tailwind CSS デフォルト）:
  - `sm`: 640px（大画面スマートフォン）
  - `md`: 768px（タブレット）
  - `lg`: 1024px（小型ノートPC）
  - `xl`: 1280px（デスクトップ）
- モバイルファーストのアプローチ（基本はモバイル、`md:` `lg:` で拡張）
- コンテナの最大幅設定とセンタリング
- グリッドレイアウトのレスポンシブ対応（1カラム → 2カラム → 3カラム）

**実装ファイル**: `src/components/layout/ResponsiveContainer.tsx`

### 2. モバイル向けパイプラインUI最適化 🟡

**信頼性**: 🟡 *architecture.mdから妥当な推測*

SimplePipelineInterface のモバイル向け最適化。ステージ表示の省略版や、スクロールベースのナビゲーションを提供する。

- ステージ表示のコンパクト版（アイコン + 現在ステージのみ）
- 縦スクロールベースのフロー表示
- アコーディオン形式の詳細表示
- モバイル向けの簡易プログレス表示

**実装ファイル**: `src/components/SimplePipelineInterface.tsx`（レスポンシブ対応追加）

### 3. タッチ操作対応 🟡

**信頼性**: 🟡 *architecture.mdから妥当な推測*

タッチデバイスでの操作性向上。タッチイベントの処理と、タッチ操作に最適化されたUIの提供。

- タッチターゲットの最小サイズ: 44x44px
- スワイプ操作のサポート（ステージ間の遷移等）
- タッチフィードバック（押下時のハイライト）
- ピンチズームの制御（意図しないズームの防止）
- ホバー状態の代替（タッチデバイスではロングプレス等）

**実装ファイル**: 各コンポーネント（タッチ対応追加）

### 4. 小画面表示の最適化 🟡

**信頼性**: 🟡 *architecture.mdから妥当な推測*

小画面デバイス（スマートフォン 320-414px）での表示最適化。

- フォントサイズの調整（最小14px）
- 余白の調整（コンパクトなレイアウト）
- モーダル/ダイアログのフルスクリーン表示
- 画像/図解の自動スケーリング
- キーボード表示時のレイアウト調整
- セーフエリア（ノッチ等）への対応（`env(safe-area-inset-*)`）

**実装ファイル**: 各コンポーネント（小画面対応追加）

### 5. モバイルデバイス検出・最適化 🔵

**信頼性**: 🟡 *architecture.mdから妥当な推測*

デバイスタイプの検出と、それに応じた最適化の適用。

- ユーザーエージェントまたは画面サイズによるデバイス判定
- タッチ対応の検出（`window.matchMedia('(hover: none)')`）
- 接続速度の検出（`navigator.connection`）に応じた品質調整
- デバイスのメモリ/能力に応じたプレビュー解像度の自動調整

**実装ファイル**: `src/hooks/useDeviceCapabilities.ts`

## 注意事項

- モバイルファーストのアプローチを採用し、基本スタイルをモバイル向けに定義し、`md:` `lg:` で拡張すること
- タッチイベントの処理では `passive` オプションに注意し、スクロール性能を低下させないこと
- CSS `touch-action` プロパティを適切に設定し、意図しないブラウザジェスチャーを防止すること
- iOS Safari での100vh問題に対応すること（`-webkit-fill-available` の使用）
- viewport metaタグの設定を確認すること（`width=device-width, initial-scale=1, viewport-fit=cover`）
- パフォーマンスを考慮し、モバイルではアニメーションを控えめにすること（`prefers-reduced-motion` の尊重）
