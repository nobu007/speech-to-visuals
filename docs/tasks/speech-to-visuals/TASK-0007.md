## 実装詳細

### 1. Supabase クライアント初期化 (src/integrations/supabase/client.ts) 🔵

**信頼性**: 🔵 *architecture.md データベース構成・note.md Supabase 2.58より*

ブラウザ側 Supabase クライアントの初期化。

機能:
- `createClient()` を使用したクライアント初期化
- `SUPABASE_URL` と `SUPABASE_ANON_KEY` からの設定読み込み
- セッション永続化の設定（localStorage）
- シングルトンパターンによるクライアント再利用
- 初期化失敗時のエラーハンドリング

**実装ファイル**: `src/integrations/supabase/client.ts`

### 2. 認証コンテキストプロバイダー (src/integrations/supabase/auth.ts) 🔵

**信頼性**: 🔵 *architecture.md 認証方式・api-endpoints.md 認証セクションより*

React 認証コンテキストの実装。

機能:
- `AuthProvider` コンポーネント: 認証状態の管理
- `useAuth()` フック: 現在のユーザー・セッション情報の提供
- `signIn()`: メール/パスワードによるサインイン
- `signUp()`: 新規ユーザー登録
- `signOut()`: サインアウト
- `session`: 現在のセッション情報（アクセストークン含む）
- `user`: 現在のユーザー情報
- `loading`: 認証状態ローディングフラグ
- セッション変更のリスナー（`onAuthStateChange`）

**実装ファイル**: `src/integrations/supabase/auth.ts`

### 3. JWT トークン検証 (src/integrations/supabase/verify-jwt.ts) 🔵

**信頼性**: 🔵 *api-endpoints.md 認証・architecture.md Supabase Auth JWTベースより*

バックエンド用の JWT 検証ユーティリティ。

機能:
- `verifyJWT(token: string)`: JWT トークンの検証
- Supabase JWT シークレットを使用した署名検証
- トークン有効期限のチェック
- ペイロードからのユーザー情報抽出（sub, email, role）
- 検証失敗時のエラースロー

**実装ファイル**: `src/integrations/supabase/verify-jwt.ts`

### 4. データアクセスレイヤー (src/integrations/supabase/repository.ts) 🔵

**信頼性**: 🔵 *database-schema.sql・REQ-405・architecture.md データベース構成より*

RLS 対応のデータアクセス関数。

機能:
- `getProjects(userId: string)`: ユーザーのプロジェクト一覧取得
- `getProject(userId: string, projectId: string)`: 単一プロジェクト取得
- `createProject(userId: string, data: CreateProjectInput)`: プロジェクト作成
- `updateProject(userId: string, projectId: string, data: UpdateProjectInput)`: プロジェクト更新
- `deleteProject(userId: string, projectId: string)`: プロジェクト削除
- 全関数は Supabase クライアントの `auth.uid()` を利用し RLS に準拠

**実装ファイル**: `src/integrations/supabase/repository.ts`

### 5. ストレージアクセスレイヤー (src/integrations/supabase/storage.ts) 🔵

**信頼性**: 🔵 *database-schema.sql・NFR-102・architecture.md ストレージ構成より*

Supabase Storage へのアクセス関数。

機能:
- `uploadAudio(userId: string, file: File)`: 音声ファイルのアップロード
- `getAudioUrl(path: string)`: 音声ファイルの公開URL取得
- `deleteAudio(userId: string, path: string)`: 音声ファイルの削除
- ファイルパス形式: `{userId}/{filename}`
- ファイルサイズ検証（50MB上限）
- MIMEタイプ検証（MP3/WAV/OGG/M4A）

**実装ファイル**: `src/integrations/supabase/storage.ts`

## 統合テスト要件

### 統合テスト1: サインイン → データアクセス → サインアウト フロー 🔵

**テスト内容**: 完全な認証フロー。サインイン → プロジェクト作成 → プロジェクト取得 → サインアウト → データアクセス拒否
**期待結果**: 認証済み状態ではCRUD操作が成功し、サインアウト後はデータアクセスが拒否される

### 統合テスト2: 認証付きAPI リクエストのエンドツーエンド確認 🔵

**テスト内容**: Express API サーバーに JWT を含むリクエストを送信し、認証ミドルウェアがユーザーを特定してRLS対応データアクセスが行われることを確認
**期待結果**: 認証済みリクエストは成功し、未認証リクエストは401エラーとなる

## UI/UX要件

### ローディング状態 🔵
認証状態確認中はローディングスピナーを表示する。`loading` フラグが `true` の間はアプリケーションコンテンツを表示しない。

### エラー表示 🟡
認証エラー（サインイン失敗、トークン期限切れ）はユーザーフレンドリーなエラーメッセージで表示する。自動リフレッシュ失敗時はサインイン画面にリダイレクトする。

### モバイル対応 🔵
ログインフォームはモバイル画面サイズに対応したレスポンシブデザインとする。

### アクセシビリティ 🔵
フォーム要素には適切な `label` を設定し、エラーメッセージは `aria-live` 領域で通知する。

## 注意事項

- Supabase クライアントはブラウザ環境とサーバー環境で初期化方法が異なることに注意
- JWT 検証は `SUPABASE_JWT_SECRET` を使用する。この値はサーバー側でのみ使用し、クライアントに露出しない
- `anon` キーはクライアント側で安全に使用できるが、`service_role` キーはバックエンドのみで使用する
- セッションリフレッシュは Supabase SDK が自動で行うが、エラーハンドリングを実装すること
- Supabase クライアントのモックは Supabase が提供するヘルパーまたはカスタムモックを使用する
