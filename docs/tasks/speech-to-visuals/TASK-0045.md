## 実装詳細

### 1. EnhancedErrorRecoveryクラス実装 🔵

**信頼性**: 🔵 *PIPELINE_FLOW.md §7, dataflow.mdエラーハンドリングフローより*

エラー発生時の回復処理を管理するクラス。リトライ戦略、フォールバック処理、ユーザー通知を統合的に制御する。

```typescript
interface ErrorRecoveryConfig {
  maxRetries: number;
  retryDelayMs: number;
  backoffMultiplier: number;
  recoveryStrategies: Map<ErrorType, RecoveryStrategy>;
  notificationHandler: ErrorHandler;
}

interface RecoveryStrategy {
  type: 'retry' | 'fallback' | 'notify' | 'abort';
  maxAttempts: number;
  fallbackFn?: () => Promise<StageOutput>;
  userMessage: string;
}

interface RecoveryResult {
  recovered: boolean;
  strategy: RecoveryStrategy;
  attempts: number;
  finalOutput?: StageOutput;
  error?: ClassifiedError;
}
```

**実装ファイル**: `src/quality/enhanced-error-recovery.ts`

### 2. ErrorClassifierクラス実装 🔵

**信頼性**: 🔵 *PIPELINE_FLOW.md §7より*

発生したエラーを種別ごとに分類するモジュール。ファイル形式エラー、ファイルサイズ超過、LLM APIエラー、レンダリングエラーなどの分類を行う。

```typescript
enum ErrorType {
  FILE_FORMAT_INVALID = 'FILE_FORMAT_INVALID',
  FILE_SIZE_EXCEEDED = 'FILE_SIZE_EXCEEDED',
  LLM_API_ERROR = 'LLM_API_ERROR',
  LLM_RATE_LIMITED = 'LLM_RATE_LIMITED',
  LLM_TIMEOUT = 'LLM_TIMEOUT',
  RENDERING_ERROR = 'RENDERING_ERROR',
  RENDERING_OOM = 'RENDERING_OOM',
  NETWORK_ERROR = 'NETWORK_ERROR',
  STORAGE_ERROR = 'STORAGE_ERROR',
  QUALITY_GATE_FAILED = 'QUALITY_GATE_FAILED',
  UNKNOWN = 'UNKNOWN',
}

interface ClassifiedError {
  type: ErrorType;
  severity: 'low' | 'medium' | 'high' | 'critical';
  stage: number;
  originalError: Error;
  userMessage: string;
  recoverable: boolean;
  suggestedAction: string;
}
```

**実装ファイル**: `src/quality/error-classifier.ts`

### 3. エラー通知ハンドラー実装 🔵

**信頼性**: 🔵 *dataflow.mdエラーハンドリングフローより*

エラー発生時のユーザー通知を管理するハンドラー。エラー重要度に応じた通知レベルの制御、通知メッセージのローカライズ、WebSocket経由のリアルタイム通知を行う。

```typescript
interface ErrorNotification {
  jobId: string;
  errorType: ErrorType;
  severity: 'low' | 'medium' | 'high' | 'critical';
  userMessage: string;
  suggestedAction: string;
  timestamp: Date;
  recoverable: boolean;
}
```

**実装ファイル**: `src/quality/enhanced-error-recovery.ts`

### 4. ユーザー主導エラー回復統合 🔵

**信頼性**: 🔵 *要件定義REQ-037・src/quality/user-guided-error-recovery.ts より*

ユーザーが回復方法を選択できる対話型エラー回復を統合する。11カテゴリのエラー分類（file_format/file_size/transcription/analysis/layout/rendering/api/network/memory/timeout/unknown）、4段階の深刻度評価（low/medium/high/critical）、自動/手動回復戦略の選択、回復成功率の追跡を実装する。

```typescript
interface UserGuidedErrorRecovery {
  analyzeError(error: Error): ErrorGuidance;
  getRecoveryOptions(errorId: string): RecoveryStrategy[];
  executeRecovery(errorId: string, strategyId: string): RecoveryResult;
  trackRecoverySuccess(errorId: string, strategyId: string): void;
}
```

**実装ファイル**: `src/quality/user-guided-error-recovery.ts`

## 単体テスト要件

### テストケース1: ファイル形式エラーの分類 🔵

**Given**: サポートされていないファイル形式（例: .txt）がアップロードされる
**When**: ErrorClassifier.classify()を呼び出す
**Then**: ErrorType.FILE_FORMAT_INVALIDとして分類され、適切なユーザーメッセージが返される

**テストファイル**: `tests/unit/quality/error-classifier.test.ts`

### テストケース2: ファイルサイズ超過エラーの処理 🔵

**Given**: 100MBを超えるファイルがアップロードされる
**When**: ErrorClassifier.classify()を呼び出す
**Then**: ErrorType.FILE_SIZE_EXCEEDEDとして分類され、最大サイズがユーザーメッセージに含まれる

**テストファイル**: `tests/unit/quality/error-classifier.test.ts`

### テストケース3: LLM APIエラーの自動回復 🔵

**Given**: Gemini APIが一時的なエラー（429/500）を返す
**When**: EnhancedErrorRecovery.recover()を呼び出す
**Then**: 指数バックオフでリトライし、最大試行回数後にフォールバックまたは通知を行う

**テストファイル**: `tests/unit/quality/enhanced-error-recovery.test.ts`

### テストケース4: レンダリングエラーの処理 🔵

**Given**: Remotionレンダリング中にOOMエラーが発生する

**テストファイル**: `tests/unit/quality/error-classifier.test.ts`

### テストケース5: 自動回復フロー 🔵

**Given**: 回復可能なエラーが発生する
**When**: リカバリ戦略がretryに設定されている

**テストファイル**: `tests/unit/quality/enhanced-error-recovery.test.ts`

### テストケース6: ユーザー主導エラー回復 🔵

**Given**: ユーザーに回復オプションが提示されるエラーが発生する
**When**: ユーザーが回復戦略を選択する
**Then**: 選択された回復戦略が実行され、回復結果が追跡される

**テストファイル**: `tests/unit/quality/user-guided-error-recovery.test.ts`

### テストケース7: エラーカテゴリ分類 🔵

## 注意事項

- エラーメッセージはユーザーに分かりやすい表現に変換し、技術的な詳細はログにのみ記録すること
- 自動回復の試行回数・間隔は設定可能にすること（デフォルト: 3回、指数バックオフ）
- クリティカルエラー（データ損失の可能性）は即座に通知し、自動回復を試行しないこと
- エラーログはSupabaseのエラーログテーブルに永続化すること
