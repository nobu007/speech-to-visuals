Express REST API によるバッチ処理エンドポイントの実装。POST /api/v1/batch/jobs によるジョブ作成、GET /api/v1/batch/jobs/:jobId によるジョブ状態取得、POST /api/v1/batch/jobs/:jobId/cancel によるジョブキャンセルを提供する。最大3並列のジョブ実行制御とジョブID管理を行う。

## 実装詳細

### 1. バッチジョブCRUDエンドポイント 🔵

**信頼性**: 🔵 *api-endpoints.md バッチ処理セクションより*

POST /api/v1/batch/jobs, GET /api/v1/batch/jobs/:jobId, POST /api/v1/batch/jobs/:jobId/cancel の3つのエンドポイントを実装する。リクエストのバリデーション、ジョブの作成・取得・キャンセル処理、適切なHTTPステータスコードとエラーレスポンスを返す。

**実装ファイル**: `src/api/batch-processing-api.ts`

```typescript
// エンドポイント定義
POST /api/v1/batch/jobs        → ジョブ作成 (202 Accepted)
GET  /api/v1/batch/jobs/:jobId → ジョブ取得 (200 OK)
POST /api/v1/batch/jobs/:jobId/cancel → ジョブキャンセル (200 OK)
```

### 2. ルーティング定義 🔵

**信頼性**: 🔵 *api-endpoints.md ルーティングセクションより*

Express Router を用いたバッチ処理ルートの定義。ミドルウェアによる認証・バリデーション・レート制限の適用。

**実装ファイル**: `src/api/routes/batch.ts`

### 3. 並列処理制御 🔵

**信頼性**: 🔵 *api-endpoints.md 並列処理セクションより*

同時実行ジョブ数を最大3に制限するセマフォベースの並列処理制御を実装する。キューイング机制により4つ目以降のジョブは待機状態となる。

**実装ファイル**: `src/api/batch-processing-api.ts`

### 4. 進捗追跡 🔵

**信頼性**: 🔵 *api-endpoints.md 進捗追跡セクションより*

各ジョブの処理ステージごとの進捗を追跡し、ジョブ状態オブジェクトとして管理する。進捗率、現在のステージ、ファイルごとの状態を含む。

**実装ファイル**: `src/api/batch-processing-api.ts`

### 5. エラーハンドリング 🔵

**信頼性**: 🔵 *api-endpoints.md エラーセクションより*

以下のエラーコードを実装する:
- `VALIDATION_ERROR` (400): リクエストパラメータのバリデーションエラー
- `TOO_MANY_FILES` (429): バッチファイル数上限超過
- `JOB_NOT_FOUND` (404): 指定されたジョブIDが存在しない
- `JOB_ALREADY_COMPLETED` (409): 既に完了したジョブのキャンセル試行

**実装ファイル**: `src/api/batch-processing-api.ts`

## 単体テスト要件

### テストケース1: ジョブ作成 🔵

**Given**: 有効なファイルリストとオプションを含むリクエスト
**When**: POST /api/v1/batch/jobs を実行
**Then**: ステータス202が返却され、ジョブIDと初期状態が含まれるレスポンスが返される

**テストファイル**: `tests/unit/api/batch-processing-api.test.ts`

### テストケース2: ジョブ取得 🔵

**Given**: 存在するジョブID
**When**: GET /api/v1/batch/jobs/:jobId を実行
**Then**: ステータス200が返却され、ジョブの状態・進捗・ファイル情報が含まれるレスポンスが返される

**テストファイル**: `tests/unit/api/batch-processing-api.test.ts`

### テストケース3: ジョブキャンセル 🔵

**Given**: 実行中のジョブID
**When**: POST /api/v1/batch/jobs/:jobId/cancel を実行
**Then**: ステータス200が返却され、ジョブがキャンセル状態に遷移する

**テストファイル**: `tests/unit/api/batch-processing-api.test.ts`

### テストケース4: 並列処理制限 🔵

**Given**: 既に3つのジョブが実行中
**When**: 4つ目のジョブ作成リクエストを送信
**Then**: ジョブは作成されるが待機状態となり、実行中ジョブの完了後に開始される

**テストファイル**: `tests/unit/api/batch-processing-api.test.ts`

### テストケース5: レート制限 🔵

**Given**: 短時間に大量のリクエストを送信
**When**: レート制限の閾値を超過
**Then**: ステータス429が返却され、適切なエラーメッセージが含まれる

**テストファイル**: `tests/unit/api/batch-processing-api.test.ts`

### テストケース6: バリデーションエラー 🔵

**Given**: 無効なパラメータを含むリクエスト
**When**: POST /api/v1/batch/jobs を実行

**テストファイル**: `tests/unit/api/batch-processing-api.test.ts`

**When**: GET /api/v1/batch/jobs/:jobId を実行
**Then**: ステータス404が返却され、JOB_NOT_FOUND エラーコードが含まれる

**テストファイル**: `tests/unit/api/batch-processing-api.test.ts`

### テストケース8: ジョブ完了後キャンセルエラー 🔵

**Given**: 既に完了したジョブID
**When**: POST /api/v1/batch/jobs/:jobId/cancel を実行
