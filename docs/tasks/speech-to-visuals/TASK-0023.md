## タスク概要

図解タイプ別レイアウト戦略の選択・実行・結果管理を行うレイアウトエンジンのコアモジュールを実装する。`LayoutStrategy` インターフェースの定義、戦略レジストリによる戦略の登録と取得、`LayoutResult` データ構造の生成、およびキャンバスサイズ計算機能を提供する。全5種類の図解タイプ（flow/tree/timeline/matrix/cycle）に対応する戦略選択の基盤を構築する。

## 実装詳細

### 1. LayoutStrategy インターフェース定義 🔵

**信頼性**: 🔵 *ZERO_OVERLAP_DESIGN.md §2 より*

```typescript
interface LayoutStrategy {
  name: string;
  apply(nodes: Node[], edges: Edge[]): LayoutResult;
  canEscapeLocalMinimum: boolean;
  estimateComplexity(nodes: Node[]): number;
}
```

`LayoutStrategy` インターフェースは全レイアウト戦略の共通契約を定義する。各戦略は `name`（戦略名）、`apply`（レイアウト実行）、`canEscapeLocalMinimum`（局所最適脱出可否）、`estimateComplexity`（計算複雑度推定）を実装する。

**実装ファイル**: `src/visualization/layout-engine.ts`

### 2. LayoutResult データ構造 🔵

**信頼性**: 🔵 *ZERO_OVERLAP_DESIGN.md §2, dataflow.md 機能3 より*

```typescript
interface LayoutResult {
  nodes: PositionedNode[];
  edges: LayoutEdge[];
  canvas: { width: number; height: number };
  metrics: LayoutMetrics;
}
```

`LayoutResult` はレイアウト計算の結果を保持する。位置付きノード（`PositionedNode`）、レイアウト済みエッジ（`LayoutEdge`）、キャンバスサイズ（`canvas`）、およびレイアウト品質指標（`LayoutMetrics`）を含む。`LayoutMetrics` にはオーバーラップ数、エッジ交差数、アスペクト比を含める。

**実装ファイル**: `src/visualization/layout-engine.ts`

### 3. 戦略レジストリ実装 🔵

**信頼性**: 🔵 *ZERO_OVERLAP_DESIGN.md §3.1 より*

図解タイプ（flow/tree/timeline/matrix/cycle）と戦略名をキーにして `LayoutStrategy` を登録・取得するレジストリパターンを実装する。重複登録の検出、未登録タイプへのアクセス時のエラー処理、戦略一覧の取得機能を提供する。

**実装ファイル**: `src/visualization/strategies/base-strategy.ts`

### 4. キャンバスサイズ計算 🔵

**信頼性**: 🔵 *ZERO_OVERLAP_DESIGN.md §2.3, architecture.md パフォーマンスセクション より*

全ノードのバウンディングボックスを計算し、パディングを加えてキャンバスサイズを決定する。1920x1080を基準とし、ノード分布に応じて動的にスケーリングする。アスペクト比 16:9 を維持しつつ、ノードが収まる最小サイズを算出する。

**実装ファイル**: `src/visualization/layout-engine.ts`

### 5. LayoutEngine オーケストレータ 🔵

**信頼性**: 🔵 *ZERO_OVERLAP_DESIGN.md §3.1, dataflow.md 機能3 より*

`LayoutEngine` クラスは DiagramData を受け取り、図解タイプに基づいて適切な戦略を選択し、レイアウト計算を実行するオーケストレータとして機能する。戦略のフォールバックチェーンを管理し、パフォーマンス指標を追跡する。

**実装ファイル**: `src/visualization/layout-engine.ts`

## 単体テスト要件

### テストケース1: 戦略選択ロジック 🔵

**Given**: DiagramData のタイプが flow/tree/timeline/matrix/cycle のいずれか
**When**: LayoutEngine に DiagramData を渡してレイアウトを要求
**Then**: 図解タイプに対応する正しい LayoutStrategy が選択される

**テストファイル**: `tests/visualization/layout-engine.test.ts`

### テストケース2: キャンバスサイズ計算 🔵

**Given**: 複数ノードが配置されたグラフ
**When**: キャンバスサイズを計算
**Then**: 全ノードがキャンバス内に収まり、アスペクト比が16:9に近いこと

**When**: 戦略の apply メソッドを実行
**Then**: LayoutResult が nodes/edges/canvas/metrics を含み、metrics.overlapCount が数値であること

**テストファイル**: `tests/visualization/layout-engine.test.ts`

**テストファイル**: `tests/visualization/strategies/base-strategy.test.ts`

### テストケース5: エッジケース（空グラフ・単一ノード） 🔵

**Given**: ノード0個のグラフ、またはノード1個のグラフ

**テストファイル**: `tests/visualization/layout-engine.test.ts`
