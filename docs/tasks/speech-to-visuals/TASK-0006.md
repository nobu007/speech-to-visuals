## 実装詳細

### 1. Express サーバーエントリーポイント (src/api/server.ts) 🔵

**信頼性**: 🔵 *architecture.md バックエンド構成・api-endpoints.md ベースURLより*

Express 5.1 アプリケーションのエントリーポイントを作成する。

設定内容:
- Express アプリケーションの初期化
- JSON ボディパーサー（limit: 50MB、REQ-402 準拠）
- CORS ミドルウェアの適用
- Helmet セキュリティヘッダーの適用
- Rate limiter の適用
- Socket.IO サーバーの統合
- ルーターのマウント（`/api/v1`）
- エラーハンドリングミドルウェアの最終設定
- ポート3001でのリッスン（環境変数 `PORT` で上書き可能）

**実装ファイル**: `src/api/server.ts`

### 2. CORS 設定 (src/api/middleware/cors.ts) 🔵

**信頼性**: 🔵 *architecture.md バックエンド構成・api-endpoints.md セキュリティより*

CORS ミドルウェアの設定。

- 開発環境: `http://localhost:8080`（Vite 開発サーバー）を許可
- 本番環境: 設定可能な許可オリジン（環境変数で管理）
- 許可メソッド: GET, POST, PUT, DELETE, OPTIONS
- 許可ヘッダー: Content-Type, Authorization
- 認証情報の送信: 有効（credentials: true）

**実装ファイル**: `src/api/middleware/cors.ts`

### 3. Socket.IO 統合 (src/api/socket.ts) 🔵

**信頼性**: 🔵 *architecture.md バックエンド構成・note.md Socket.IO 4.8 より*

Socket.IO サーバーの設定と Express への統合。

- Socket.IO サーバーの初期化
- CORS 設定（Express と同一）
- 認証ミドルウェア（JWT 検証）
- 接続・切断イベントのハンドリング
- 進捗イベントのブロードキャスト用インターフェース定義

イベント種別:
- `job:progress`: バッチジョブ進捗通知
- `job:complete`: バッチジョブ完了通知
- `job:error`: バッチジョブエラー通知

**実装ファイル**: `src/api/socket.ts`

### 4. ルーター基本構成 (src/api/routes/index.ts) 🔵

**信頼性**: 🔵 *api-endpoints.md・architecture.md API設計より*

API ルーターの基本構成を作成する。

- `/api/v1/health`: ヘルスチェック（GET）
- `/api/v1/batch`: バッチ処理ルーター（後続タスクで実装）
- 404 ハンドラー: 未定義ルートの処理

**実装ファイル**: `src/api/routes/index.ts`

### 5. ヘルスチェックエンドポイント (src/api/routes/health.ts) 🔵

**信頼性**: 🔵 *api-endpoints.md・architecture.md より*

ヘルスチェックエンドポイントの実装。

レスポンス形式:
```json
{
  "success": true,
  "data": {
    "status": "ok",
    "version": "1.0.0",
    "timestamp": "2026-04-27T00:00:00.000Z",
    "uptime": 12345.678
  }
}
```

**実装ファイル**: `src/api/routes/health.ts`

### 6. エラーハンドリングミドルウェア (src/api/middleware/error-handler.ts) 🔵

**信頼性**: 🔵 *api-endpoints.md 共通エラーフォーマット・PIPELINE_FLOW.md §7.2 より*

統一エラーレスポンスフォーマットの実装。

エラーレスポンス形式:
```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "エラーメッセージ",
    "details": {}
  }
}
```

機能:
- 4xx クライアントエラーの処理
- 5xx サーバーエラーの処理
- バリデーションエラーの処理
- 本番環境ではスタックトレースを非表示

**実装ファイル**: `src/api/middleware/error-handler.ts`

### 7. Express 型拡張 (src/api/types.ts) 🔵

**信頼性**: 🔵 *architecture.md・Express 5.1 型定義より*

Express の Request/Response 型拡張。

- `AuthRequest`: Request 型を拡張し `user` プロパティを追加
- `ApiResponse<T>`: レスポンスヘルパー型

**実装ファイル**: `src/api/types.ts`

## 注意事項

- Express 5.1 の破壊的変更に注意（`app.listen` の戻り値、エラーハンドリング等）
- Socket.IO は Express サーバーと同じ HTTP サーバーイン stance を共有すること
- Helmet はデフォルト設定を使用し、必要に応じて CSP を緩和する
- Rate limit の設定値は環境変数で調整可能にすること
- エラーハンドリングミドルウェアは他の全ミドルウェアの後に配置すること
