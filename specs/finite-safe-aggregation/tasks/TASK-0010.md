## タスク概要

round-18 sweep が明示トリアージしなかった 2 領域を移行する:

1. **sweep 正本リストで「移行（ウェーブ 5 傍流・任意）」と宣言されたまま未実行だった
   `enhanced-error-recovery.ts` の loadMetrics interface mean 6 サイト**
   （355/356/357/420 + 471/821 の pre-filter+reduce イディオム）。
   同じ `loadMetrics.averageResponseTime` 由源の sibling が 2 サイトは
   `Number.isFinite` pre-filter 付き・2 サイトは素通しという in-file invariant-split。
2. **registry discovery rule の roots（analysis/quality/export）に含まれていなかった
   `src/monitoring/` 大陸**。`production-monitor.ts` に 3 欠陥:
   - `updateAggregateMetrics` の raw fold mean（public API `recordSuccess(latency)` 由来）
   - **floor-rank percentile の最後の hand-rolled twin**（`sorted[Math.floor(n*0.95)] || 0` —
     clamp 無し・NaN を「速い 0」に偽装する falsy fallback 付き）
   - component 每 incremental mean が `successes` 除算 + raw latency fold で、
     非有限 1 件で `averageLatency` が**永久 NaN 化**（running mean は回復しない）

加えて `error-recovery-health-tracker.ts:215`（avgRecovery）— r18 exclusion 理由は
「internally generated deltas (203/243/245)」と 215 を含んでおらず、実際は
`report.summary.recoverySuccessRate` という interface 値。NaN score は
`score < degradationThreshold` 比較を false 化し degraded stage が無判定で通過する
（silent-green）。
