## エピック1: 音声入力と文字起こし

### ストーリー 1.1: 音声ファイルのアップロードと文字起こし 🔵

**信頼性**: 🔵 *README.md クイックスタート・PIPELINE_FLOW.md Stage 1・src/transcription/ より*

**私は** コンテンツクリエイター **として**
**音声ファイルをアップロードしてテキストに文字起こししたい**
**そうすることで** 音声内容をテキストベースで確認・活用できる

**関連要件**: REQ-001, REQ-003, REQ-004

**詳細シナリオ**:

1. ユーザーが MP3/WAV/OGG/M4A 形式の音声ファイル（最大50MB）をドラッグ＆ドロップでアップロード
2. システムが Whisper モデルを用いて自動言語検出付き文字起こしを実行
3. タイムスタンプ付き SRT キャプションとプレーンテキストが出力される
4. 処理進捗がリアルタイムで UI に表示される

**前提条件**:
- 音声ファイルが対応形式であること
- ファイルサイズが50MB以下であること
- 音声長が1秒以上であること

**制約事項**:
- 文字起こし精度は Whisper base モデルで約85%
- 処理速度はリアルタイムの約2倍

**優先度**: Must Have

## エピック2: 内容分析と図解自動生成

### ストーリー 2.1: テキストから図解タイプ自動検出 🔵

**信頼性**: 🔵 *SYSTEM_CORE.md §4.1・PIPELINE_FLOW.md Stage 2・src/analysis/diagram-detector.ts より*

**私は** コンテンツクリエイター **として**
**文字起こしされたテキストから適切な図解タイプを自動検出したい**
**そうすることで** 手動で図解タイプを選択する手間が省ける

**関連要件**: REQ-005, REQ-006, REQ-007, REQ-008

**詳細シナリオ**:

1. 文字起こしテキストが3-15秒のセグメントに自動分割される
2. 言語検出（日本語/英語/自動）が実行される
3. コンテンツ複雑さがスコアリングされ、LLM モデルが自動選択される
4. Gemini LLM がエンティティ抽出・関係性抽出・図解タイプ検出を実行
5. 11種類の図解タイプから最適なものが判定される

**前提条件**:
- 有効な GOOGLE_API_KEY が環境変数に設定されていること
- LLM API がアクセス可能であること

**制約事項**:
- 図解タイプ検出精度は92%
- LLM レスポンス時間 P95: 20秒以内

**優先度**: Must Have

---

### ストーリー 2.2: フォールバックによる安定した分析 🔵

**信頼性**: 🔵 *SYSTEM_CORE.md §4.2・PIPELINE_FLOW.md §4.1 より*

**私は** ユーザー **として**
**LLM API が一時的に利用できなくても図解結果を受け取りたい**
**そうすることで** どんな状況でも作業が止まらない

**関連要件**: REQ-009, REQ-010, REQ-101

**詳細シナリオ**:

1. LLM Primary（Flash/Pro）で分析を試行
2. レートリミット・タイムアウト等で失敗した場合、ジッタ付き指数バックオフで最大3回リトライ
3. リトライも失敗した場合、Fallback LLM に切り替え
4. Fallback LLM も失敗した場合、ルールベース V1 で確実に結果を生成

**前提条件**:
- 3層フォールバック機構が実装されていること

**優先度**: Must Have

---

### ストーリー 2.3: セマンティックキャッシュによる高速再分析 🔵

**信頼性**: 🔵 *PIPELINE_FLOW.md §5.1・src/analysis/llm-cache.ts より*

**私は** ユーザー **として**
**同じような内容の音声を再度処理する際に高速に結果を得たい**
**そうすることで** 処理時間と API コストを削減できる

**関連要件**: REQ-011, REQ-103

**詳細シナリオ**:

1. 新しい音声の文字起こしテキストが分析モジュールに入力される
2. セマンティックキャッシュが類似度 > 0.9 の既存結果を検索
3. ヒットした場合、LLM 呼び出しをスキップしてキャッシュ結果を返す
4. ミスの場合、LLM 分析を実行し結果をキャッシュに保存

**前提条件**:
- キャッシュが有効化されていること（200エントリ、TTL 120分）

**備考**: コールドスタート時はヒット率0%、使用後4週間で30%を目標

**優先度**: Should Have

## エピック3: 図解レイアウトと動画作成

### ストーリー 3.1: ゼロオーバーラップの図解レイアウト生成 🔵

**信頼性**: 🔵 *SYSTEM_CORE.md §4.3・PIPELINE_FLOW.md Stage 3・src/visualization/ より*

**私は** コンテンツクリエイター **として**
**図解のノードやエッジが重ならないように自動レイアウトしたい**
**そうすることで** 見やすく整理された図解が得られる

**関連要件**: REQ-012, REQ-013, REQ-014, NFR-302

**詳細シナリオ**:

1. 検出された図解タイプに応じてレイアウト戦略が選択される（Flow/Tree/Timeline/Matrix/Cycle）
2. ノード位置とエッジパスが計算される
3. オーバーラップ検出が全ノードペアに対して実行される
4. オーバーラップが検出された場合、フォースダイレクト法で最大100回反復して解消
5. キャンバスサイズ計算（1920x1080基準）とセンタリングが適用される

**前提条件**:
- 有効な DiagramData（1ノード以上、エッジ参照が有効）が入力されていること

**制約事項**:
- レイアウト計算は1図解あたり2秒以内
- オーバーラップ数は常に0

**優先度**: Must Have

---

### ストーリー 3.2: アニメーション付き動画の自動生成 🔵

**信頼性**: 🔵 *PIPELINE_FLOW.md Stage 4-5・src/remotion/・QUALITY_METRICS.md §3.4-3.5 より*

**私は** コンテンツクリエイター **として**
**図解データからアニメーション付きの説明動画を自動生成したい**
**そうすることで** 音声と図解を組み合わせた動画コンテンツを簡単に作成できる

**関連要件**: REQ-025, REQ-026, REQ-027, REQ-028, REQ-029, REQ-030, REQ-301

**詳細シナリオ**:

1. レイアウトデータとSRTキャプションがシーン同期される
2. ノードのフェードイン（0.3秒）、エッジの描画アニメーション（0.5秒）が設定される
3. 図解タイプ別のアニメーション戦略が自動選択される
4. SRTキャプションがパースされ、キャプションオーバーレイが表示される
5. Remotion が React コンポーネントとしてアニメーションを生成
6. 1080p 30fps で MP4 動画としてレンダリングされる
7. 音声トラックが動画に統合される

**前提条件**:
- 有効なレイアウトデータが入力されていること
- 音声トラックが存在すること
- SRTキャプションファイルが生成されていること

**制約事項**:
- キャプション同期精度: ±50ms
- 出力ファイルサイズ: 5-10MB/分

**優先度**: Must Have
