## 実装詳細

### 1. diagram_projects テーブル作成 🔵

**信頼性**: 🔵 *database-schema.sql・supabase/migrations/ より*

`diagram_projects` テーブルを以下のスキーマで作成する。

主要カラム:
- `id`: UUID（主キー、デフォルト gen_random_uuid()）
- `user_id`: UUID（auth.users 参照、NOT NULL）
- `title`: text（NOT NULL）
- `audio_file_path`: text（音声ファイルパス）
- `audio_duration_ms`: integer（音声再生時間ミリ秒）
- `status`: text（デフォルト 'idle'）
- `transcription`: jsonb（文字起こし結果）
- `scenes`: jsonb（シーンデータ配列）
- `video_url`: text（生成動画URL）
- `quality_score`: numeric（品質スコア）
- `created_at`: timestamptz（デフォルト now()）
- `updated_at`: timestamptz（デフォルト now()）

**実装ファイル**: `supabase/migrations/00001_create_diagram_projects.sql`

### 2. Row Level Security (RLS) ポリシー 🔵

**信頼性**: 🔵 *database-schema.sql・REQ-405・NFR-102 より*

diagram_projects テーブルに対して RLS を有効化し、以下のポリシーを設定する。

- **SELECT**: ユーザーは自分の `user_id` と一致する行のみ参照可能
- **INSERT**: 認証済みユーザーは自分の `user_id` で新規行を作成可能
- **UPDATE**: ユーザーは自分の行のみ更新可能
- **DELETE**: ユーザーは自分の行のみ削除可能

ポリシー関数: `auth.uid() = user_id`

**実装ファイル**: `supabase/migrations/00001_create_diagram_projects.sql`（同一ファイル内）

### 3. インデックス作成 🔵

**信頼性**: 🔵 *database-schema.sql・NFR-001（パフォーマンス要件）より*

クエリパフォーマンス最適化のため以下のインデックスを作成する。

- `idx_diagram_projects_user_id`: user_id カラムの B-tree インデックス
- `idx_diagram_projects_status`: status カラムの B-tree インデックス
- `idx_diagram_projects_created_at`: created_at の降順インデックス

**実装ファイル**: `supabase/migrations/00001_create_diagram_projects.sql`（同一ファイル内）

### 4. 自動更新トリガー 🔵

**信頼性**: 🔵 *database-schema.sql・Supabase 標準パターンより*

`updated_at` カラムを自動更新するトリガーを作成する。

- `set_updated_at()`: BEFORE UPDATE トリガー関数
- `diagram_projects_set_updated_at`: UPDATE 時に set_updated_at() を実行するトリガー

**実装ファイル**: `supabase/migrations/00001_create_diagram_projects.sql`（同一ファイル内）

### 5. RLS ポリシー検証SQL 🔵

**信頼性**: 🔵 *REQ-405・NFR-102 より*

RLS ポリシーが正しく機能することを確認するための検証SQLスクリプトを作成する。

- ポリシー一覧確認: `pg_policies` システムビューのクエリ
- ユーザー分離確認: 異なるユーザーでのデータアクセステスト
- 権限昇格テスト: 他ユーザーデータへのアクセス拒否確認

**実装ファイル**: `supabase/migrations/verify_rls_policies.sql`

## 注意事項

- マイグレーションファイルは冪等性を確保すること（`IF NOT EXISTS` の使用）
- RLS ポリシーは `USING` 句と `WITH CHECK` 句の両方を設定すること
- `gen_random_uuid()` は PostgreSQL 14+ または pgcrypto 拡張が必要なことに注意
- jsonb カラムのデータ構造は TypeScript 型定義（TASK-0002）と整合性を保つこと
- Supabase の `service_role` キーはRLSをバイパスするため、バックエンドでのみ使用すること
