## 実装詳細

### 1. トークン使用量トラッカー 🔵

**信頼性**: 🔵 *llm-service.ts LLMServiceStats分析より*

LLM API呼び出しのレスポンスからトークン使用量を抽出・記録する。Gemini APIはusageMetadataフィールドでトークン数を返す。

**実装ファイル**: `src/analysis/token-usage-tracker.ts`（新規）

```typescript
interface TokenUsageRecord {
  requestId: string;
  model: 'gemini-2.5-flash' | 'gemini-2.5-pro';
  inputTokens: number;
  outputTokens: number;
  totalTokens: number;
  timestamp: number;
  stage: 'analysis' | 'fallback' | 'cache-warmup';
}

interface CostEstimate {
  flashCost: number;    // $ per million tokens
  proCost: number;      // $ per million tokens
  totalCost: number;
  costByStage: Record<string, number>;
}
```

### 2. コスト推定エンジン 🔵

**信頼性**: 🔵 *Gemini API pricing 公式ドキュメントより*

Gemini Flash ($0.075/M input, $0.30/M output) と Pro ($1.25/M input, $5.00/M output) の価格に基づくリアルタイムコスト推定。

**実装ファイル**: `src/analysis/cost-estimator.ts`（新規）

### 3. 予算アラートシステム 🔵

**信頼性**: 🔵 *既存QualityMonitor・PerformanceDashboardアラートパターンより*

セッション累積コストが予算閾値を超えた場合に警告を発行する。

**実装ファイル**: `src/analysis/budget-alert.ts`（新規）

```typescript
interface BudgetConfig {
  sessionBudget: number;    // e.g., $1.00 per session
  dailyBudget: number;      // e.g., $10.00 per day
  alertThreshold: number;   // e.g., 0.8 (80%)
}
```

### 4. PerformanceDashboard統合 🔵

**信頼性**: 🔵 *既存performance-dashboard.tsメトリクス拡張パターンより*

コストメトリクスを既存のPerformanceDashboardに統合し、リアルタイム表示を可能にする。

**実装ファイル**: `src/monitoring/performance-dashboard.ts`（拡張）

## 単体テスト要件

### テストケース1: トークン使用量記録が正確 🔵

**信頼性**: 🔵 *llm-service.ts既存テストパターンより*

**Given**: API呼び出しレスポンス（inputTokens: 1500, outputTokens: 500）
**When**: recordTokenUsage()を呼び出し
**Then**: TokenUsageRecordが正確に記録されること

**テストファイル**: `tests/analysis/token-usage-tracker.test.ts`

### テストケース2: コスト推定が正確 🔵

**信頼性**: 🔵 *Gemini pricing仕様より*

**Given**: Flash model, 10K input tokens, 2K output tokens
**When**: estimateCost()を呼び出し
**Then**: $0.075 * 10 + $0.30 * 2 = $1.35 であること

### テストケース3: 予算アラートが閾値で発火する 🔵

**信頼性**: 🔵 *既存アラートテストパターンより*

**Given**: sessionBudget: $1.00, alertThreshold: 0.8
**When**: 累積コストが$0.80に到達
**Then**: アラートが発行されること

### テストケース4: ステージ別コスト内訳が正確 🔵

**Given**: analysis: $0.50, fallback: $0.10, cache-warmup: $0.02
**When**: getCostByStage()を呼び出し
**Then**: 各ステージのコストが正確に返されること

### テストケース5: トークン使用量の上限チェック 🔵

**Given**: maxTokensPerRequest: 4096
**When**: 5000トークン使用のリクエスト
**Then**: 警告が発行されること

### テストケース6: コストメトリクスのDashboard統合 🔵

**Given**: 3回のAPI呼び出しのトークン記録
**When**: Dashboard.getCostMetrics()を呼び出し
**Then**: セッション合計コスト・平均コスト・ステージ別内訳が返されること
