# TASK-0161: LLMキャッシュデバウンステスト追加

## 概要

LLMCache の `scheduleSave()` debounce ロジックに対する専用タイミングテストを追加し、debounce 設定時のタイミング-sensitive なパスの回帰を防止する。

## 背景

コミット 138c695 で debounce 実装を追加したが、既存テスト（`tests/analysis/llm-cache.test.ts`）は `persistDebounceMs: 0` の同期モードのみテストしており、debounce タイマーの結合・キャンセル・即時フラッシュのタイミング検証が不在だった。

AI Hub フィードバック: "the debounce logic in llm-cache.ts (scheduleSave, destroy, persist cancellation) has only 9 changed lines in the existing test file and likely needs dedicated debounce-interval tests to prevent timing regressions"

## Acceptance criteria

- [x] 専用テストファイル `tests/analysis/llm-cache-debounce.test.ts` が存在する
- [x] `jest.useFakeTimers()` でタイマー精度を制御している
- [x] 6カテゴリのタイミングテストが含まれる（coalescing / destroy / persist / accuracy / clearExpired / sync fallback）
- [x] ディスクロード済みキャッシュとdebounceの相互作用テストが含まれる
- [x] saveToDisk失敗後のdebounce timer 復旧テストが含まれる
- [x] 全テストが通過する（既存テストへの回帰なし）

## 実装内容

- `tests/analysis/llm-cache-debounce.test.ts` を新規作成（15テスト）
- `jest.useFakeTimers()` でタイマー精度を制御
- 6カテゴリのタイミングテスト:
  1. scheduleSave coalescing (3テスト)
  2. destroy() cancellation (3テスト)
  3. persist() immediate flush (3テスト)
  4. timer interval accuracy (2テスト)
  5. clearExpired re-scheduling (2テスト)
  6. persistDebounceMs: 0 fallback (2テスト)

## 検証結果

- テスト結果: 15/15 passed
- 既存テスト影響: なし（65/65 passed）
