## 背景

TASK-0243 が定義した義務 C は「`tests/unit exact-0` + `tests total ≤ 100` の 2 gate 通過 + manual unskip 発火」。第1ゲート（unit exact-0）は Phase 165 / TASK-0251、第2ゲート（total ≤ 100）は Phase 167 / TASK-0253 で通過済み。残るは (1) 残存 9 ディレクトリ 36 ノード（pipeline 11・quality 9・analysis 6・api 2・lib 2・remotion 2・(root) 2・acceptance 1・config 1）の exact-0 化、(2) TASK-0243 が予告した「14 ディレクトリ個別 pin → tests 全体 exact-0 pin 集約」、(3) 同 TASK が spec 化した ratchet 終了条件 3 ケース（TC-342-01。it.skip で追加予定だったが実装は specs のみに終わっていた）の guard への実装と発火、の 3 点。本タスクはこれらを 1 commit に閉じて義務 C を完結させる。

**重要な前提の訂正**: TC-342-01 は「`tests/guards/non-null-assertion-census.test.ts` に 3 ケースの `it.skip(...)` が追加されている」と記載しているが、Phase 156 の実装 commit (655f297f) は specs 3 ファイル + src/tests 2 ファイルのみを触り guard への it.skip 追加は行われていなかった（`git log -S "stillRoom" -- tests/` が空 = 当該コードは一度も存在していない）。両ゲートが既に通過済みの今、skip してから手動で unskip する儀式は RED-as-normal-state を生まない dead weight になるため、本タスクは 3 ケースを **active（GREEN 成立）形式で直接追加** する — これが「manual unskip 発火」の実体であり、pin が 0 に集約されたこの commit 以降、終了条件は恒久的に監視される。
