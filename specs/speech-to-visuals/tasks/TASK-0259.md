## 背景

Phase 170（REQ-364）は RTPM `getSnapshot()` の quality trio を finite-or-null 化し、Phase 171（REQ-365/366）は LLM response time 2 field に実測 producer を生やした。残る quality trio は REQ-368 設計決定で「producer なし fail-closed のまま（METRIC UNAVAILABLE が計装を促す）」としていたが、3 field のうち **`layoutOverlapRate` だけは別扱いが正しい**: overlap は品質パイプライン由来の外部 subsystem ではなく **repo 内に canonical 実測 scan（`quality-estimators.ts` の `countLayoutOverlaps` pairwise scan）が既に存在する**ため、単一 TASK の最小 verifiable 範囲に収まる。LLM 系と同じ「fail-loud の行き先」を quality 系に適用する。

## 修正

### REQ-372: `recordPipelineQuality` producer

`RealTimePerformanceMonitor` に `recordPipelineQuality(measuredScenes, layoutOverlapCount)` を追加:

- `getSnapshot().quality.layoutOverlapRate` = `measuredScenes > 0 ? layoutOverlapCount : null`
- **報告前・degenerate（0 scene）report は null** — scan が走らなかった run の vacuous 0 は eq-0 zero-tolerance blocker gate を無測定で pass させる（REQ-364 class）
- ingestion chokepoint で `sanitizeFinite`（`recordLLMRequest` と同一 leak class）・last report wins・`reset()` で消去
- **設計決定（count であって rate ではない）**: QualityMonitor `layoutOverlap`（"0 is perfect"）と eq-0 gate が読むのは同じ量。rate 化は所有者のいない分母を要求し empty layout で vacuous 0 を返す。field 名の `Rate` は legacy として field doc に単位を明記
- `transcriptionAccuracy` / `avgSceneQuality` は引き続き producer なし fail-closed（estimator proxy 0.90/0.85 は 0.85 blocker の上に位置し恒久 green を一段深い所で再現するだけ）

### REQ-373: 測定サイト直結 wiring（bridge を recordMetrics に置かない）

canonical scan が実 result に走る 3 site で report:

1. `SimplePipeline` success path（`countLayoutOverlaps(qualitySignals)` の直後）
2. `MainPipeline.buildQualityMetrics`
3. `FrameworkIntegratedPipeline.extractQualityMetrics`（`detectLayoutOverlaps` の直後）

**設計決定**: `QualityMonitor.recordMetrics` 内に bridge を置かない — recordMetrics の他 caller（gemini-analyzer per-diagram record・pipeline-orchestrator partial records・SimplePipeline failure path）は DEFAULT `layoutOverlap: 0` を未測定のまま渡すため、そこで bridge すると未測定 0 が eq-0 blocker gate に再流入する。failure path は report しない（失敗 run は layout を測定していない）。

### REQ-374: gate が実測値で本物に fail する pin

adaptive-quality-gates の 'Layout Overlap Rate' gate（eq 0・blocker）に measured count 2 を渡す test — `passed=false`・message は `≠`（METRIC UNAVAILABLE と区別）・blockers ≥1・`deploymentReady=false`。Phase 170 の null→UNAVAILABLE test と対になり、fail-closed / fail-loud-on-real-defect の両側面を検証。
