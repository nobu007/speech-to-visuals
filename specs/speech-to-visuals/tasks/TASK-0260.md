## 背景

Phase 173（REQ-373 設計決定）は RTPM 側の `layoutOverlapRate` に実測 producer を生やしたが、**同じ eq-0 zero-tolerance 構造が pipeline 側 QualityMonitor（0-100 scale）にもう一回立っている**: `recordMetrics` の DEFAULT は `layoutOverlap: 0` で、gemini-analyzer の per-diagram record・orchestrator の非 layout stage record・SimplePipeline failure path が「測定していない run」にこの DEFAULT を渡す。旧 DEFAULT は (i) `calculateOverallScore` の `layoutOverlap === 0 → +5` zero-overlap bonus を無測定 run に与え、(ii) eq-0 zero-tolerance gate を無測定で恒久 GREEN にする（REQ-364「gate と正確に結合した捏造定数」class）。さらに orchestrator layout stage は `layoutOverlap: score < 0.7 ? 1 : 0`（composite score からの count 捏造）+ `edgeCompleteness: score`（score laundering）という**捏造二重構造**だった。

## 修正

### REQ-375: count-or-null 契約

`src/pipeline/quality-monitor.ts` の `QualityMetrics.layoutOverlap` を `number | null`（count・0 is perfect・**null = unmeasured**）とし、`recordMetrics` DEFAULT を `null` に。**設計決定**: RTPM `layoutOverlapRate`（Phase 173・count）と同量・同契約に揃える — 片方だけ finite-or-null だと eq-0 blocker が 2 経路のうち未測定側だけ通過する。消費側 null 集約:

- `checkThresholds`: `!== null &&` で eq-0 gate を測定時のみ評価
- `calculateOverallScore`: `=== 0` strict equality は null を落とすため bonus は測定 0 のみ（ comment で明記）
- `compareToBaseline`: avg 計算の filter と loop 両方で null skip
- `regression-detector`: baseline/current いずれか null で metric skip（NaN % 行の阻止）
- `improvement-detector`: null で Layout Quality 機会を立てない
- `simple-pipeline` failure path: `layoutOverlap` key を渡さない（DEFAULT null が効く）

### REQ-376: orchestrator 実測 producer

private `measureLayoutOverlaps(layoutResults)` — run の最終 layout 全数を canonical `countOverlapPairs(nodes, 0)`（predicate `nodesOverlap`・spacing 0 = `countLayoutOverlaps`/`detectLayoutOverlaps`/layout quality gate と同一 source）で scan し `{measuredLayouts, overlapCount}` を返す。`measuredLayouts` は ≥1 node を持つ layout 数（`optimizeLayoutQuality` の scoredCount と同 semantics）で、`> 0` のときだけ `recordStageQuality` が `layoutOverlap: overlapCount` を記録（全 empty layout run は記録なし = DEFAULT null・vacuous 0 なし）。`edgeCompleteness` はこの record から除去（producer は analysis-time GeminiAnalyzer edge-ratio に一元化）。

### REQ-377: MW-042 mutation

**scope 決定**: orchestrator の layout stage への RTPM `recordPipelineQuality` wiring は追加しない — Phase 173 が live 3 site に配線済みで、orchestrator は production 経由でない dormant export（ESM mock 負荷だけ増える）。
