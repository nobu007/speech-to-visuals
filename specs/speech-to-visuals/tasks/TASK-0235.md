### 1. alert-rules.test.ts 55 node → 0（fail-loud `requireAlertRule` helper）

`.find()` 結果の `rule!.expr` / `rule!.severity` / `rule!.for` / `rule!.description` / `rule!.runbookUrl` 計 55 node を、ファイル内 helper に置換:

```ts
function requireAlertRule(config: AlertingConfig, alert: string): AlertRule {
  const rule = config.groups[0].rules.find(r => r.alert === alert);
  if (rule === undefined) {
    throw new Error(`alert rule not found: ${alert}`);
  }
  return rule;
}
```

**挙動保存の根拠**: 旧コードの不在時挙動は (a) `rule!.expr` の `TypeError: Cannot read properties of undefined (reading 'expr')` または (b) bare `expect(rule).toBeDefined()` の失敗 — いずれも test RED。helper は不在時に欠落 alert 名を含む `Error` を throw するため **同一 verdict（RED）でメッセージが診断可能**。存在時は同一 assertion を narrow された `rule` に対して実行。`expect(rule).toBeDefined()` 行（7 件）は helper が同保証を担うため削除 — テストの意図（rule の存在検証）は helper の throw が保持。Phase 144 `requireSceneId` と同型の fail-loud accessor。

### 2. export-job-queue-dlq.test.ts 39 node → 0（fail-loud `requireDefined` helper）

`findJob()` / `replayDeadLetterJob()` / `dequeue()` の 3 種の optional 戻り値（`QueuedExportJob | undefined`）計 39 node を、label 付き generic helper に置換:

```ts
function requireDefined<T>(value: T | undefined, label: string): T {
  if (value === undefined) {
    throw new Error(`${label} returned undefined`);
  }
  return value;
}
```

- 単一参照: `expect(requireDefined(queue.findJob(job.jobId), `findJob(${job.jobId})`).retryCount).toBe(1);`
- 複数参照（`replayed` ×5 など）: 1 回の捕捉に集約し以降は narrow された値を使用
- `expect(dlqJob).toBeDefined()` / `expect(replayed).toBeDefined()` は helper が同保証を担うため削除

**挙動保存の根拠**: 旧 `!` は不在時 `TypeError` = RED。helper は label（`findJob(<id>)` 等・出典を含む）付き Error を throw = 同一 verdict。
