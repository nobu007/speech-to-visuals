## 背景

Phase 170/171（REQ-364〜368）は RTPM/adaptive-gates 系の捏造 metric を finite-or-null 契約 + producer で閉じた。しかし QualityMonitor に直結する **reporter 側** には同型の捏造が 2 site 残存していた（L3 台帳「0.85 metric-DEFAULT coupled-to-GATE-threshold」の pipeline/analysis-side live instance）:

1. **simple-pipeline.ts**（MISSED-SIBLING-SITE）: MainPipeline（`buildQualityMetrics`）と FrameworkIntegratedPipeline は `quality-estimators.ts` の canonical estimators に委譲済みだが、SimplePipeline の success-path は `transcriptionAccuracy: transcript.length > 0 ? 0.9 : 0`・`sceneSegmentationF1: scenes.length > 0 ? 0.85 : 0`・`layoutOverlap: 0`（「enhanced layout engine が保証」comment）を報告。各値は `detectViolations` threshold（0.85/0.75/0）と正確に結合し恒久 green。
2. **gemini-analyzer.ts**: `entityExtractionF1: nodes.length > 0 ? 0.85 : 0.3`。0.85 > threshold 0.80 で非空抽出は恒久 green、singleton（正規 0.70）や過密（0.50）の実 signal が無報告。

## 修正

### REQ-369: SimplePipeline → canonical estimators 委譲

`quality-estimators.ts` に `PipelineQualitySignals = Pick<PipelineResult, 'success' | 'scenes' | 'duration'>` を追加し（SimplePipeline は `PipelineResult` を持たない）、success-path で:

- `transcriptionAccuracy: estimateTranscriptionAccuracy(signals)`
- `sceneSegmentationF1: estimateSegmentationQuality(signals)`
- `layoutOverlap: countLayoutOverlaps(signals)`（「保証」comment 削除 — 実測 count）
- `duration: scenes.reduce(Σ durationMs)` を自前計算

failure-path の fail-loud 0 系・pipeline-orchestrator（実 confidence 報告済み）は不変。

**GOTCHA**: `transcript = segments.map(s => s.text).join(' ')` は空 text 複数でも「空白のみの非空文字列」→ `transcript.length > 0` はほぼ恒真。MW-040 mutation (a) の退化 fixture は単一 `['']` segment にしないと捏造 0.9 === canonical 0.9 で RED が立たない（11 空segment で最初 RED にならなかったのを実測）。

### REQ-370: GeminiAnalyzer → scoreNodeDensity 委譲

`nodes.length > 0 ? 0.85 : 0.3` → `nodes.length > 0 ? scoreNodeDensity(nodes.length) : 0`。

**設計決定**: 空抽出は hard 0 — `scoreNodeDensity(0)` = 0.50 は「degenerate density」用で「empty extraction」用ではない。旧 0.3「partial」も廃止（抽出完了後に無いものは無い）。

### REQ-371: 単一 source 構造化

- estimator 8 関数の引数を `PipelineResult` → `PipelineQualitySignals` に緩める（構造的部分型で既存呼び出し不変）
- density→score scale を `scoreNodeDensity` として切り出し export — `estimateEntityExtractionQuality` と GeminiAnalyzer が同一実装を読む（duplicate-formula class 封じ・gemini 側 scale drift は estimators test pin で検出）
