## 背景

Phase 182 (TASK-0266) が quality-monitor の `stages.every(...)` vacuous pass（空配列で vacuously true）を撲滅した際、**array 型 criteria を持つ公開評価 API** に同型 sibling が残存していた（**missed-sibling-site class** — 本 repo の CORE recurring bug class）。grep 全 `.every(` で、literal 固定 key object（main-pipeline/transcriber/diagram-detector/scene-segmenter の `Object.values(...).every(...)`）は構造的に空になり得ないことを確認のうえ、caller-supplied array を `safeArray` で受ける 2 site を対象とした:

| site | 旧実装 | 実欠陥 |
|---|---|---|
| `src/framework/iteration-manager.ts` `evaluateSuccessCriteria` | `safeArray(cycle.successCriteria).map(...)` → `results.every(r => r.met)` | `DevelopmentCycle` は caller-supplied（`new IterationManager(cycle)`・非空検証なし）。criteria ゼロの cycle は `allMet: true` を無証拠主張し、唯一の pipeline caller（`framework-integrated-pipeline.ts:161-165`）が `allMet` を iteration status `'success'` と commit trigger（`shouldCommit`）に直接写像するため無根拠成功 + 無根拠 commit |
| `src/quality/quality-gate.ts` `StageQualityGate.evaluate` | `safeArray(config.criteria).map(...)` → `results.every(r => r.passed)` | `registerGate()` は criteria を検証しない。criteria ゼロ登録 gate は `passed: true`・results 0 件で stage を無評価パス。**旧挙動は 2 test が明示 pin する stale GREEN**（`tests/quality/quality-gate.test.ts` `// no criteria = all pass`・`src/quality/__tests__/quality-gate.test.ts` `should pass with no criteria`） |

## 修正

1. **`evaluateSuccessCriteria` fail-closed + loud row** — 空 criteria は `allMet: false` + synthetic row（criterion `(no success criteria defined)`・reason `Cycle declares no successCriteria; success cannot be claimed`）
2. **`StageQualityGate.evaluate` fail-closed + loud row** — 空 criteria は `passed: false` + synthetic row（`criterionName: 'noCriteriaRegistered'`・details に gate 名 + `stage N`）。同 file の `evaluateStage` gateNotFound precedent（missing gate → `passed: false` + `gateNotFound` row）と同型
