### 1. EdgeCrossingMinimizer クラス 🟡

**信頼性**: 🟡 *REQ-080 定義に基づく新規実装*

**実装ファイル**: `src/visualization/edge-crossing-minimizer.ts`

```typescript
export interface EdgeCrossingResult {
  crossingCount: number;
  crossingPairs: Array<{
    edge1: string;  // edge id
    edge2: string;  // edge id
    point: { x: number; y: number };
  }>;
  minimizedNodes: PositionedNode[];
  minimizedCrossings: number;
  improvementPercent: number;
}

export class EdgeCrossingMinimizer {
  detectCrossings(
    nodes: PositionedNode[],
    edges: LayoutEdge[]
  ): Pick<EdgeCrossingResult, 'crossingCount' | 'crossingPairs'>;

  minimizeCrossings(
    nodes: PositionedNode[],
    edges: LayoutEdge[],
    maxIterations?: number
  ): EdgeCrossingResult;

  isGraphType(diagramType: DiagramType): boolean;
}
```

### 2. 線分交差判定 🔵

**信頼性**: 🔵 *計算幾何学の標準アルゴリズム*

2つの線分が交差するかを外積（cross product）を用いて判定。O(n²)の全ペア比較で実装し、ノード数が多い場合は空間ハッシュ（既存spatial-hash.ts）で最適化。

### 3. スプリング埋め込みヒューリスティクス 🟡

**信頼性**: 🟡 *一般的なグラフ描画最適化手法*

Force-directed layout の変種で、交差エッジに反発力を加えてノード位置を微調整。既存の `OverlapResolver` の force-directed手法と同パターン。

### 4. エッジ再ルーティング 🟡

**信頼性**: 🟡 *REQ-080 の再ルーティング概念*

交差を回避するようベジェ曲線の制御点を調整。直線エッジを曲線化して交差を回避。

## 基本的なテスト要件

### 交差検出テスト 🔵

**信頼性**: 🔵 *幾何学的テスト*

- 2辺がX字に交差 → crossingCount = 1
- 平行な2辺 → crossingCount = 0
- 同じ始点・終点のエッジ → 適切に処理

### 最小化テスト 🟡

**信頼性**: 🟡 *最適化結果のテスト*

- 交差ありレイアウト → 最小化後に交差数減少
- 既に交差なしレイアウト → 変更なし
- 最大反復回数到達 → 結果を返す

### グラフ型判定テスト 🔵

**信頼性**: 🔵 *DiagramType列挙型テスト*

- flow/flowchart/network/conceptmap → true
- timeline/matrix/cycle → false
