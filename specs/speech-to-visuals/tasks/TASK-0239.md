## 実施内容（2026-08-20 完了）

### 1. phase32-quality-pipeline.test.ts 38 node → 0（fail-loud `requireMetrics`）

`result.metrics` の `result.metrics!.field` 読みを、戻り型 `Partial<ExtendedPipelineMetrics>` の helper に集約（`PipelineResult`/`ExtendedPipelineMetrics` を `@/pipeline/types` から import）。`const { optimizationAttempts!, labelTruncationCount! } = result.metrics!` の destructure 抑制は通常 field 読みに。sizing loop 内の `x!` は `if (sizing === undefined) throw` narrowing に。直前の `expect(result.metrics).toBeDefined()` は helper の throw が同保証を担うため折りたたみ（Phase 149〜151 と同一判断）。

**挙動保存の根拠**: 旧コードの不在時挙動は `undefined.field` TypeError = RED。helper は不在時に Error を throw するため **同一 verdict（RED）でメッセージが診断可能**。

### 2. label-sizing-pipeline.test.ts 15 node → 0（`NonNullable` 版 `requireMetrics`）

### 3. batch.test.ts 23 node → 0（fail-loud null 戻り lookup 3 種）

`manager.getJobStatus(jobId)`（`BatchJobStatus | null`）の `status!.field` を `requireJobStatus(manager, jobId)` に・cancel token（`| null`）を `requireCancelToken(manager, jobId)` に・`startBatch()` の戻り `startedId: string | null` を `requireStartedId(startedId)` に。**null-guard 根拠**: 3 API とも不在時に `null` を返すため helper は undefined でなく **null** を guard する（Phase 149/151 と同一）。直前の `expect(…).not.toBeNull()` 対は折りたたみ。

### 4. secure-download-pipeline.test.ts 20 node → 0（fail-loud `requireDefined<T>`）

### 5. test_pipeline_health_smoke.test.ts 17 node → 0（fail-loud optional-field helper 3 種）

`result.timingReport`（`?`）→ `requireTimingReport`（戻り型 `NonNullable<SmokeOrchestratorResult['timingReport']>`）・`result.healthReport`（`?`）→ `requireHealthReport`（`PipelineHealthReport`）・`report.costComparison`（`| null`）→ `requireCostComparison`（`NonNullable<PipelineHealthReport['costComparison']>`）。**未 export 型は `NonNullable<T['field']>` 導出で回避**（`StageTimingReport` は `@/pipeline` から export されないため import 不可）。

### 6. importance-scaler.test.ts 21 node → 0（fail-loud `requireModule` + `findNode`）

definite-assignment `let MindMapStrategy!: typeof import('@/visualization/strategies/mindmap-strategy')` / `NetworkStrategy!: …`（`!:` 2 node）を `let mindmapMod: typeof import(…) | undefined` holder に変換し、各テストで `const { MindMapStrategy } = requireModule(mindmapMod, 'mindmap-strategy');` と destructure:

```ts
function requireModule<T>(mod: T | undefined, name: string): T {
  if (mod === undefined) {
    throw new Error(`${name} module not loaded (beforeAll failed)`);
  }
  return mod;
}
```

旧 `new MindMapStrategy()` の不在時挙動 `new undefined()` TypeError = RED に対し、helper は module 名入り Error を throw し同一 verdict。`result.nodes.find(n => n.id === …)` の `node!.field` は `findNode(result, id)`（id 付き RED）に、算術 `bNode.width! / 2` は `(bNode.width ?? Number.NaN) / 2` に置換。

### 7. flow-strategy.test.ts 20 node / tree-strategy.test.ts 18 node → 0（`findNode` + `centerXOf`/`centerYOf`）

`result.nodes.find(…)` の `nodeA!` 系を `findNode(result, id)` に。center 算術 `node.x + node.width! / 2` は:

```ts
function centerXOf(node: PositionedNode): number {
  return node.x + (node.width ?? Number.NaN) / 2;
}
```

（tree 側は `centerYOf` = `node.y + (node.height ?? Number.NaN) / 2`）。**`?? Number.NaN` の根拠**: 旧 `width!` は runtime 値を変えない checker 抑制のため `width === undefined` なら旧コードは `NaN` を算出（比較 matcher は fail = RED）。`?? Number.NaN` は同じ undefined→NaN 伝播を明示的に保存し、かつ jest matcher の `number | undefined` 型エラー（`toBeGreaterThan` 等）を解消する。

### 8. complex-layout-engine.test.ts 18 node → 0（`findLayoutNode` + `centerOf`）

`DiagramLayout` 型を import し `type DiagramLayoutNode = DiagramLayout['nodes'][number]` を導出（`@stv/core` の layout node は `w`/`h` が optional）。`layout.nodes.find(…)` を `findLayoutNode(layout, id)` に・center 算術を `centerOf(node)`（`(node.w ?? Number.NaN)`/`(node.h ?? Number.NaN)`）に・bounds 検査 `node.x + node.w!` は `node.x + (node.w ?? Number.NaN)` に。
