## タスク概要

コード規模監査（code-size-audit）の `collectMetrics()` がリポジトリ全体の TS/JS ファイルを走査している問題を修正し、`src/` ディレクトリのみを監査対象とする。

## 背景

現状の `src/config/code-size-audit.ts` の `collectMetrics()` は `rootDir` 配下の全 TS/JS ファイルを走査する（`node_modules`, `dist`, `.git`, `coverage` はスキップ）。これにより tests/（116ファイル/34K行）、scripts/（27ファイル/8K行）、supabase/（5ファイル/1K行）もカウントされ、実際のプロダクションコード（src/: 327ファイル/96,414行）は SYSTEM_CONSTITUTION V2.4 制限内であるにも関わらず、監査結果が NON-COMPLIANT となる。

## 完了条件

- [x] `collectMetrics()` に `srcDir` オプションを追加し、デフォルトで `src/` のみを走査する
- [x] CLI（scripts/code-size-audit.ts）が `src/` のみを監査対象として実行される
- [x] `--all` フラグで従来通りリポジトリ全体を走査できる（オプション）
- [x] 既存テスト（tests/config/code-size-audit.test.ts）が全て通過する
- [x] 新規テストで src/ スコープ限定動作を検証する
- [x] TypeScript型エラー0件・ESLintエラー0件を維持

## 実装詳細

**修正ファイル**: `src/config/code-size-audit.ts`
- `collectMetrics(rootDir: string)` → `collectMetrics(rootDir: string, options?: { srcOnly?: boolean })`
- `srcOnly: true` の場合、`src/` サブディレクトリのみを走査
- デフォルトは `srcOnly: true`

**修正ファイル**: `scripts/code-size-audit.ts`
- `runAudit()` 呼び出し時に `srcOnly: true` を設定（デフォルト）

**テストファイル**: `tests/config/code-size-audit.test.ts`（拡張）
- `srcOnly: true` 時に src/ 配下のみカウントされることを検証
- `--all` フラグで全ファイルカウントされることを検証
