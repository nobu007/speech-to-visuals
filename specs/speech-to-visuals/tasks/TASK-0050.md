### 1. バッチジョブCRUD統合テスト 🔵

**信頼性**: 🔵 *api-endpoints.md バッチ処理エンドポイントセクションより*

POST /api/v1/batch/jobs, GET /api/v1/batch/jobs/:jobId, POST /api/v1/batch/jobs/:jobId/cancel の3つのエンドポイントについて、正常系・異常系の統合テストを実装する。データベースとの連携を含めた実際のリクエスト・レスポンスを検証する。

**実装ファイル**: `tests/integration/api.test.ts`

```typescript
describe('Batch Job API Integration', () => {
  describe('POST /api/v1/batch/jobs', () => {
    test('有効なリクエストでジョブが作成される');
    test('バリデーションエラーが適切に返される');
    test('ファイル数上限超過でエラーが返される');
  });

  describe('GET /api/v1/batch/jobs/:jobId', () => {
    test('存在するジョブIDで状態が取得される');
    test('存在しないジョブIDで404エラーが返される');
  });

  describe('POST /api/v1/batch/jobs/:jobId/cancel', () => {
    test('実行中ジョブがキャンセルされる');
    test('完了済みジョブのキャンセルで409エラーが返される');
  });
});
```

### テストケース1: POST /api/v1/batch/jobs 正常系 🔵

## 注意事項

- テスト用のSupabaseインスタンスまたはモックを使用し、本番データに影響を与えないこと
- テスト間の独立性を確保し、各テストケースの前にデータベース状態をリセットすること
- レート制限テストはテスト専用の低い閾値を設定し、テスト実行時間を合理的に保つこと
- WebSocketテストはSocket.IOのテストクライアントを使用し、接続・切断を確実に行うこと
- セキュリティテストは実際の攻撃パターンを含めず、設定の正しさを検証することに留めること
- CI/CD環境での並列実行を考慮し、ポート番号やリソースの競合を避けること
