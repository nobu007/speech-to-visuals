## タスク概要

TASK-0114で構築したWorker基盤を利用し、CPU集約的な処理をWeb Workersに移行する。主な対象は（1）エクスポートエンジンのレンダリング処理と（2）複雑レイアウトエンジンのノード配置計算。これによりメインスレッドのブロッキングを防止し、UI応答性を向上させる。

## 実装詳細

### 1. エクスポートWorker実装 🔵

**信頼性**: 🔵 *既存 enhanced-export-engine.ts の `workerPool: Worker[]` フィールドより*

`src/workers/export-worker.ts` を実装する。

- エクスポートエンジンからレンダリング処理（Remotion動画生成、画像エクスポート）を切り出す
- Worker内で重い計算処理を実行し、進捗をメッセージで報告
- エクスポート完了時に結果（Blob URL、ファイルサイズ等）を返却
- エラーハンドリングとタイムアウト処理

**実装ファイル**: `src/workers/export-worker.ts`

```typescript
// 実装イメージ
import { WorkerMessage, WorkerResponse } from './types';

self.onmessage = async (e: MessageEvent<WorkerMessage>) => {
  const { id, type, payload } = e.data;
  try {
    // レンダリング処理の実行
    const result = await processExport(payload);
    self.postMessage({ id, type, payload: result } satisfies WorkerResponse);
  } catch (error) {
    self.postMessage({ id, type, error: { code: 'EXPORT_ERROR', message: String(error) } } satisfies WorkerResponse);
  }
};
```

## 注意事項

- Remotionのレンダリング処理はブラウザコンテキストに依存する可能性があるため、Worker内で完結するか検証が必要
- dagreライブラリは純粋なJSなのでWorker内でそのまま利用可能
- メインスレッドとWorker間のデータはシリアライズされるため、関数やクラスインスタンスは渡せない（plain objectsのみ）
- 既存テストがWorker化の影響を受けないよう、モック/スタブの適切な設定が必要
