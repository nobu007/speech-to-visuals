### 1. checker の AST 化（REQ-336 前提 — guard-first survey）

旧 line-regex（行ベース・continuation class `[\s.,;:)\]}+*/?=<>&|{]`）には 2 種の盲点があった:

- **検出不能形状**: `!` の直後が `(` の呼び出し形 `nextJob.resolve!({…})`。Phase 144 で src/export を「10 件 → 0」とした際にこの形状が **見落とされていた**（Phase 147 の AST checker 化で初めて発見・除去 — MW-013 で旧 regex が同 mutant に 0 hit であることを実証）。
- **偽陽性**: 文字列リテラル・JSX text 内の `!`（`'Oops! Page…'`・`Generator! 🎉` 等 3 件）をカウントしていた。文字ベースの分布「24 行」にはこの偽陽性が含まれ、実 AST node は 22 件（21 正 + 1 見落とし）。

新 checker は `ts.createSourceFile`（ScriptKind.TSX/TS）で構文解析し、`ts.isNonNullExpression`（`x!`）と property/variable/parameter declaration の `exclamationToken`（`x!:`）を **AST node 単位**で数える。文字列内容・コメント・JSX text は構造的に不可視化（偽陽性ゼロ）、`f!(…)`・`x![0]`・`` `${x!}` `` 形状も検出。**TASK-0226 の line-regex rule は本 checker が SUPERSEDE**（spine 整合のためここまで意図的に同一 regex を維持してきた）。tests 側 baseline は行ベース 960 → node ベース **1096**（計数器の昇格であって回帰ではない）。
