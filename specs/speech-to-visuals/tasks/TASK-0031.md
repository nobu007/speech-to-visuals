## タスク概要

DiagramDataのタイプに基づいて最適なレイアウト戦略を自動選択するモジュールを実装する。図解タイプ（flow/tree/timeline/matrix/cycle）から主戦略とフォールバック戦略へのマッピング、フォールバックチェーンの管理、および計算複雑度の推定機能を提供する。レイアウトエンジンのエントリポイントとして機能する。

## 実装詳細

### 1. タイプ別戦略マッピング 🔵

**信頼性**: 🔵 *ZERO_OVERLAP_DESIGN.md §3.3 Table, dataflow.md 機能3 図解タイプ別戦略テーブル より*

DiagramData の図解タイプに基づいて、最適な LayoutStrategy を選択するマッピングを実装する。戦略レジストリ（TASK-0023）に登録された戦略を参照し、タイプ名をキーにして取得する。

戦略マッピングテーブル:

| タイプ | 主戦略 | フォールバック戦略 |
|--------|--------|-------------------|
| flow | Progress Force | Grid-Snap |
| tree | 階層レイアウト | Grid-Snap |
| timeline | Force（X制約） | Grid-Snap |
| matrix | Grid-Snap | N/A |
| cycle | 円形レイアウト | Force-Directed |

```typescript
interface StrategySelector {
  select(diagramType: DiagramType): LayoutStrategy;
  getFallbackChain(diagramType: DiagramType): LayoutStrategy[];
  estimateComplexity(diagramType: DiagramType, nodeCount: number): number;
}
```

**実装ファイル**: `src/visualization/strategy-selector.ts`

### 2. フォールバックチェーン 🔵

**信頼性**: 🔵 *ZERO_OVERLAP_DESIGN.md §3.1 OverlapResolver, dataflow.md 機能3 より*

主戦略でオーバーラップが解消できない場合のフォールバックチェーンを管理する。各図解タイプに対して主戦略→フォールバック戦略の順に実行し、最初に成功した戦略の結果を採用する。matrixタイプはフォールバックなし（Grid-Snap単独で常に成功）。

フォールバックチェーン実行:
1. 主戦略でレイアウト計算を実行
2. オーバーラップ数を確認
3. オーバーラップ数 > 0 の場合、フォールバック戦略に切り替え
4. フォールバック戦略で再計算
5. 全戦略失敗時はGrid-Snapで強制的にオーバーラップ0を保証

**実装ファイル**: `src/visualization/strategy-selector.ts`

### 3. 計算複雑度推定 🔵

**信頼性**: 🔵 *ZERO_OVERLAP_DESIGN.md §2 LayoutStrategy.estimateComplexity より*

図解タイプとノード数から計算複雑度を推定する。推定結果は戦略選択の最適化とパフォーマンス予測に使用する。

複雑度推定ロジック:
- flow: O(n * e)（n=ノード数, e=エッジ数）- dagreのトポロジカルソート
- tree: O(n) - 階層レイアウトは線形
- timeline: O(n) - Y固定でXのみ最適化
- matrix: O(1) - グリッド配置は一定
- cycle: O(n) - 円形配置は角度計算のみ

```typescript
estimateComplexity(diagramType: DiagramType, nodeCount: number): number {
  switch (diagramType) {
    case 'flow': return nodeCount * estimatedEdgeCount(nodeCount);
    case 'tree': return nodeCount;
    case 'timeline': return nodeCount;
    case 'matrix': return 1;
    case 'cycle': return nodeCount;
    default: return nodeCount * nodeCount;
  }
}
```

**実装ファイル**: `src/visualization/strategy-selector.ts`

### 4. デフォルト戦略 🔵

**信頼性**: 🔵 *ZERO_OVERLAP_DESIGN.md §2.3 より*

未知の図解タイプやnull/undefinedのタイプが指定された場合のデフォルト戦略を実装する。デフォルトはGrid-Snapとし、常にオーバーラップ0を保証する。エラーログを出力し、呼び出し元にデフォルト戦略が使用されたことを通知する。

**実装ファイル**: `src/visualization/strategy-selector.ts`

### 5. パイプライン統合 🔵

**信頼性**: 🔵 *dataflow.md 機能3, architecture.md パイプラインステージ構成 より*

戦略選択→レイアウト計算→オーバーラップ解消→キャンバス計算の統合パイプラインを実装する。DiagramData を入力とし、LayoutResult を出力とする単一のエントリポイントを提供する。

```typescript
async function executeLayout(data: DiagramData): Promise<LayoutResult> {
  // 1. 戦略選択
  const strategy = strategySelector.select(data.type);
  // 2. レイアウト計算
  let result = strategy.apply(data.nodes, data.edges);
  // 3. オーバーラップ解消
  result.nodes = overlapResolver.resolve(result.nodes, 100);
  // 4. キャンバス計算・センタリング
  const canvas = canvasCalculator.calculate(result.nodes);
  result.nodes = canvasCalculator.center(result.nodes, canvas);
  result.canvas = canvas;
  return result;
}
```

**実装ファイル**: `src/visualization/strategy-selector.ts`
