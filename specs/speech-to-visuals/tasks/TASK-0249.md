## 背景

TASK-0243 §義務 B は「requirements.md（正本）と architecture.md（mirror）の二重管理を、人間の手作業経由ではなく build hook / Makefile target での再生成に切り替える」こととし、TASK-0247 がその DoD を concrete 化した: (1) Makefile 不在 → generator script の新規作成が必要、(2) `specs/_doc_spine.yml` は auto-gen・gitignored → manifest 側への hook 配線、(3) architecture.md（910 行）は手書き prose → **generator を作る前に marker 契約を先に固めること**（契約なき自動生成は偽 sync を生む）。TASK-0248 §残存 obligation は本件を「未着手の最優先」として引き継いだ。

問題の構造は 2 つの実被害に出る:

1. **Phase 158〜161 の specs 債務**: 実装 commit が REQ/TC/TASK/MW を名指しても specs 同期を別 commit に分けた結果、台帳・要件に穴が残り 2〜3 フェーズ後に一括補填（meta_washed commit）された。
2. **ai-hub link:spine drift（ef80df93..251cbac8..463771ee）**: 正典 child ドキュメント追加時に再生された children ブロック / anchor メタ行が作業 commit から漏れ、コミット済みツリーがゲート失敗状態で存在した（今回の steering 指摘）。

両者とも「sync 状態が機械検査されていない」ことが根因。本タスクは契約（marker 構文 + 双方向トークン検証）を定義し `tests/guards/` で CI 強制する。**generator script と manifest hook 配線は義務 B 後半（TASK-0250）** — 契約が先に固定されることで generator の出力も同じ guard で検証可能になる。

## 契約（本タスクで固定する唯一の構文）

```
<!-- mirror:<正本ファイル名>#<正本の ## 節名>:start tokens="トークン|トークン|…" -->
…mirror region（正本の当該節の事実を prose で言い換えた領域）…
<!-- mirror:<正本ファイル名>#<正本の ## 節名>:end -->
```

- 正本ファイルは marker を置くファイルと同じディレクトリ（`specs/speech-to-visuals/`）
- 節は `## <節名>` の**完全一致**（`## 非機能要件` は hit・`## 非機能要件の実現方法` は非 hit）。節の範囲は次の `## ` まで
- tokens は verbatim 文字列（`|` 区切り）。**双方向** 検証: (a) 各トークンが正本の当該節に存在（marker が正本に無い事実を正典と偽って主張しない）、(b) 各トークンが mirror region に存在（正本更新が mirror に未伝播の drift 検出）
- 構造違反（孤立 start/end・start/end 対不一致・nest・空 region・正本ファイル/節の欠落）も violation
- **spine 系 marker（`<!-- spine:children:* -->`・`<!-- spine:references:* -->`・`<!-- spine:anchor:* -->`）は別系統**（ai-hub link:spine 管理の auto-gen ブロック）。本契約は spine ブロックの再生成を扱わない — 範囲を混ぜると偽 sync を生む
- 適用対象は「真の mirror」のみ。`## 信頼性レベル分布`（requirements）と `## 信頼性レベルサマリー`（architecture）は**母集団が異なる**（要件の信頼性 vs 設計項目の信頼性）ため mirror 対象外。`## 技術的制約`（architecture）の出典は PIPELINE_FLOW.md（docs 系）で requirements 由来ではないため対象外
