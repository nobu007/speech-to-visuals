## 主要実装項目

### 1. APNGエンコーダライブラリの選定・統合 🔵

**信頼性**: 🔵 *REQ-063・SYSTEM_CONSTITUTION.md パッケージ上限110より*

候補ライブラリの評価と選定:
- `upng-js`: 軽量PNG/APNGエンコーダ、ブラウザ・Node.js両対応
- `pngjs`: PNG読み書きライブラリ、APNG拡張が必要
- カスタムエンコーダ: PNGチャンク（acTL/fcTL/fdAT）を直接構築

選定基準: バンドルサイズ最小・APNGネイティブ対応・メンテナンス状態良好

**実装ファイル**: `package.json`, `src/export/enhanced-export-engine.ts`

### 2. encodeAPNG()の実エンコーディング実装 🔵

**信頼性**: 🔵 *src/export/enhanced-export-engine.ts 555-562行のsimulateEncoding()置換え*

現在の実装:
```typescript
private async encodeAPNG(job: ExportJob, frames: FrameData[]): Promise<EncodedVideo> {
  return {
    data: await this.simulateEncoding(frames, 'apng', 'apng'),
    ...
  };
}
```

置換後:
- フレームデータ（RGBA）をエンコーダに渡す
- FPS → フレーム遅延（ミリ秒）変換
- PNG圧縮による最適化
- エラー時のフォールバック（シミュレートに戻すのではなく、明確なエラー）

**実装ファイル**: `src/export/enhanced-export-engine.ts`

### 3. APNG実エンコーディングテスト追加 🔵

**信頼性**: 🔵 *REQ-063仕様より*

テストケース:
- PNGシグネチャ検証（先頭8バイト = 89 50 4E 47 0D 0A 1A 0A）
- acTLチャンク存在確認（アニメーション制御チャンク）
- fcTLチャンク数 = フレーム数の一致確認
- フレーム遅延がFPS設定と一致すること
- 1フレームAPNGの正常生成
- 空フレーム配列のエラーハンドリング
- Worker経由エクスポートでの実エンコーディング結果検証

**テストファイル**: `src/export/__tests__/enhanced-export-engine.test.ts`
