## 背景

TASK-0249（義務 B 前半）は marker 契約を固定して guard で CI 強制したが、残された問題は「正本を更新したときの mirror 側の作業」がまだ人間の手作業であること。義務 B の元文（TASK-0243）は「requirements.md（正本）と architecture.md（mirror）の二重管理を、人間の手作業経由ではなく build hook / Makefile target での再生成に切り替える」だった。

難しいのは **prose は機械生成できない** こと。region 全体を正本の verbatim copy にしてしまえば再生成は自明だが、それは mirror が正本の逐語複製になるだけで要件↔設計の言い換えという価値が消え、guard の検出力も実質ゼロになる（偽 sync）。本タスクの設計判断はこのトレードオフを **所有権分割** で解く:

| 領域 | 所有者 | 保証 |
|------|--------|------|
| marker 行（start/end・tokens 宣言） | 人間 | tokens 双方向検証（TASK-0249 契約・変更なし） |
| region 内の prose（正本節の言い換え） | 人間 | token 化された事実は TOKEN_MISSING_* で drift 検出 |
| region 内の sync-stamp 行 **1 行** | generator | 正本節への **あらゆる** 編集を digest 比較で検出 |

## sync-stamp 契約（本タスクで追加する唯一の構文）

```
<!-- mirror:requirements.md#非機能要件:start tokens="…" -->
<!-- sync:mirror source-digest="<正本節の正規化 sha256 先頭 12 hex>" -->
…prose（人間所有・言い換え）…
<!-- mirror:requirements.md#非機能要件:end -->
```

- digest の正規化: 行末 `\r` 除去 → 行末空白除去 → 前後空行除去 → sha256 → 先頭 12 hex。エディタ由来のノイズ（CRLF 化・行末空白付与）で偽 STALE にならない
- violation は 3 種追加: `MISSING_SYNC_STAMP`（stamp が無い）/ `DUPLICATE_SYNC_STAMP`（2 個以上）/ `STALE_SYNC_STAMP`（stamp の digest ≠ 現正本節の digest）
- **token 検証と直交する検出力**: tokens に宣言されていない事実の編集（数値の微修正・行追加など）は TASK-0249 契約を素通りするが、stamp は正本節の内容ハッシュで変わるので必ず STALE になる（MW-032 で実証）

## 実装

- `tests/guards/specs-mirror-contract.ts` — 契約モジュールに `computeSourceDigest` / `renderSyncStamp` / `SYNC_STAMP_DETECT_RE` / `SYNC_STAMP_VALUE_RE` と `validateMirrorRegions` 末尾の stamp 検証を追加。**単一ソース**: generator もこの module を import し、契約の再実装を作らない
- `scripts/sync-mirror-from-requirements.ts`（新規）— repo の generator 慣行（`sync:edge`/`verify:edge` の dual-mode）に準拠:
  - 純関数 `syncMirrorStamps(mirrorFile, content, readSource)` — 構造違反ファイルは **一切書き換えない**（fail-loud: 破損 parse 結果の周辺を書き換えると偽 sync）。startLine 降順で splice（前行番号をずらさない）・stamp 挿入は region body 先頭・冪等（2 回目は no-op）
  - `runMirrorContractCheck(specsDir)` — jest guard と同一ロジックの CLI 入口（書き込みなし）
  - CLI: `--check` = drift detector（違反で exit 1・書き込まない）/ default = sync（stamp 再生成 → post-sync 検証で残存違反 = 人手 curation 済みでない token drift があれば exit 1）
- `package.json` — `specs:mirror:check` / `specs:mirror:sync` を追加し `verify:all` の `spine:validate` 直後に `specs:mirror:check` を挿入
- `scripts/validate-spine-manifest.ts` — `spine:validate` CLI から `runMirrorContractCheck` を呼ぶ hook 配線。manifest が auto-gen・gitignored で SKIPPED でも specs/ は tracked なので mirror 検証が常に走り exit code に反映される（clean checkout / CI で gate が実 teeth を持つ — TASK-0247 調査結果 2 の実装）
- `specs/speech-to-visuals/architecture.md` — §非機能要件の実現方法 の region に初回 `specs:mirror:sync` で stamp を挿入（`source-digest="56cab125a152"`)
- `tests/guards/specs-mirror-contract.test.ts` — 12 → **23 tests**（sync-stamp fixture 5 種 + generator 6 種を追加）。最後の test「generator output passes the full contract validation」が **受入検査**: generator が再生成した region は TASK-0249 契約の tokens 双方向検証 + stamp 検証を含む検証全体を通る
