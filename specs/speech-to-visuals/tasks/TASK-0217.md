## タスク概要

`JSON.parse("1e400")` は Infinity を返し、`typeof === "number"` ガードを素通りするため、復元値が後段算術で `Infinity + 1 → Infinity`、`now - Infinity → -Infinity`、`<= 0` の閾値チェックを透過する 既知のベクタである。

`c9216907` で Lottie export verifier と `time-origin-mismatch-guard-mutation.test.ts` が FIX 済みだが、`src/quality/regression-detector.ts` の `loadBaseline()`（line 131-152）は **`JSON.parse(data).timestamp` と `JSON.parse(data).metrics.timestamp` を `new Date()` に直接渡しており、Infinity 経由の Invalid Date → NaN arithmetic → silent regression detection bypass** が成立する。本タスクは当該サイトを構造的に修正し、回帰ネット（`time-origin-mismatch-guard-mutation` と同型の structural pin）を追加する。

## 実装詳細

### 1. regression-detector `loadBaseline()` の finiteness ガード 🔵

**信頼性**: 🔵 *file:line アンカー（src/quality/regression-detector.ts:131-152）および直前の修正 c9216907 の検証パターンより*

`new Date(Infinity)` は Invalid Date を返し、後段の `getTime()` / 比較演算で NaN を伝播させ、regression detection を「比較不能 = regression なし」相当で通過させる（silent）。さらに `parsed.metrics.timestamp` 配下も同形。

**実装内容**:
- helper `coerceFiniteTimestamp(raw: unknown, label: string): number | null` を export せずローカルに置く（この 1 箇所でしか使わないため）
- `parsed.timestamp` が `typeof === 'number' && Number.isFinite(parsed.timestamp)` でなければ `logger.warn(...)` + `localStorage.removeItem` 相当（fs.unlink ベストエフォート）+ `return null`
- 両 timestamp が有限な場合のみ `this.baseline` に変換結果を格納

**実装ファイル**: `src/quality/regression-detector.ts` 行 131-152

```typescript
const finiteTimestamp = (
  raw: unknown,
  label: string,
): number | null => {
  if (typeof raw !== 'number' || !Number.isFinite(raw)) {
    logger.warn(
      `Baseline ${label} is not a finite number (got ${String(raw)}); ` +
      `rejecting baseline file ${this.baselinePath}`,
    );
    try { await fs.promises.unlink(this.baselinePath); } catch { /* best effort */ }
    return null;
  }
  return raw;
};

async loadBaseline(): Promise<BaselineData | null> {
  try {
    if (!fs.existsSync(this.baselinePath)) return null;
    const data = await fs.promises.readFile(this.baselinePath, 'utf-8');
    const parsed: unknown = JSON.parse(data);
    if (!parsed || typeof parsed !== 'object') return null;

    const tsTop = finiteTimestamp((parsed as Record<string, unknown>).timestamp, 'timestamp');
    const parsedMetrics = (parsed as Record<string, unknown>).metrics;
    if (!parsedMetrics || typeof parsedMetrics !== 'object') return null;
    const tsMetrics = finiteTimestamp(
      (parsedMetrics as Record<string, unknown>).timestamp,
      'metrics.timestamp',
    );
    if (tsTop === null || tsMetrics === null) return null;

    this.baseline = {
      ...(parsed as Partial<BaselineData>),
      timestamp: new Date(tsTop),
      metrics: {
        ...(parsedMetrics as Partial<QualityMetrics>),
        timestamp: new Date(tsMetrics),
      },
    };
    return this.baseline;
  } catch (error) {
    logger.warn(`⚠️  Failed to load baseline: ${error}`);
  }
  return null;
}
```

## 注意事項

- `new Date(Infinity)` は Invalid Date を作り、`.getTime()` は NaN を返す。**`Number.isFinite(raw)` を必ず通過させる**（`typeof === 'number'` のみでは不十分、c9216907 と同因）
- `parsed` を `unknown` 経由にせず `as any` で扱う既存パターンが多いが、ここでは型安全のため `Record<string, unknown>` 経由に統一する（既存 modernization に揃える）
- `fs.promises.unlink` を try/catch で囲むのは、ファイルが既に削除済み・エラー無害化のため
- `this.baseline = null` 復帰後、呼び出し側（`runDetection` 等）で「baseline 未確立」をハンドリングする既存パスに自然に落ちる（変更不要）
