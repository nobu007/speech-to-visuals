## 背景

**本書は Phase 161 の補填 TASK 化**である。実装は Phase 159（commit 6d7a34e5・2026-08-20）に完結していたが、対応する TASK ファイル・REQ-350 の requirements.md 登録・TC-345 の acceptance-criteria.md 登録・MW-025 の台帳登録がPhase 159 commit 単体では実施されず、Phase 161 の docs 同期（commit 本書参照）で一括補填した。

[TASK-0245 §残存 obligation](TASK-0245.md) で `隣接 live silent-corruption 候補` として先出しされていた `HealthCheckService.checkLLMHealth()` は、`realTimeMonitor.getSnapshot().llm.cacheHitRate` の backend omit / non-finite（NaN）時に:

```ts
// src/monitoring/health-check-service.ts (修正前)
if (cacheHitRate > 0.4 || totalRequests === 0) {   // undefined/NaN > 0.4 = false
  // healthy
} else if (cacheHitRate > 0.2) {                    // undefined/NaN > 0.2 = false
  // degraded
} else {
  // unhealthy: "Llm integration may have issues (NaN% cache hit rate)"
}
```

両述語が FALSE のため else 枝に落ち、`(NaN * 100).toFixed(1)` を含む fabricated unhealthy を上流 dashboard / `generateRecommendations`（CRITICAL recommendation）へ伝播させる silent corruption だった（unknown observation window に対する虚偽の critical）。

## 修正（Phase 159・commit 6d7a34e5）

`checkLLMHealth()` の `try { snapshot = realTimeMonitor.getSnapshot(); } catch …` 直後に REQ-347〜349 と同型の typeof + Number.isFinite ガードを追加:

```ts
if (!isFiniteMetric(cacheHitRate)) {
  logger?.warn?.(
    `[HealthCheck] LLM health check unavailable: backend omitted/non-finite metrics ` +
      `(cacheHitRate=${typeof cacheHitRate === 'number' ? cacheHitRate : 'undefined'})`
  );
  return {
    status: 'degraded',
    message: 'LLM integration unavailable: backend omitted/non-finite cacheHitRate',
    latency: Date.now() - startTime,
    lastChecked: Date.now(),
  };
}
```

Phase 160（commit f441e8d3）でこの inline ガードは `isFiniteMetric` 述語に統合された。
