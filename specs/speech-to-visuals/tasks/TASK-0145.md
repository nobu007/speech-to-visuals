## 実装詳細

### 1. パフォーマンスベースライン定義 🔵

**信頼性**: 🔵 *既存パフォーマンステストパターンより*

各パイプラインステージのタイミング・メモリベースラインを定義する。現在の実測値（E2E 25.2秒）を基準に設定。

**実装ファイル**: `src/pipeline/performance-baseline.ts`（新規）

```typescript
interface PerformanceBaseline {
  stage: string;
  maxDurationMs: number;    // Current baseline + 10% margin
  maxMemoryMB: number;      // Per-stage memory limit
  targetDurationMs: number; // Phase 36 target (after parallelization)
}

const BASELINES: PerformanceBaseline[] = [
  { stage: 'transcription', maxDurationMs: 8000, maxMemoryMB: 50, targetDurationMs: 8000 },
  { stage: 'analysis',      maxDurationMs: 10000, maxMemoryMB: 80, targetDurationMs: 7000 },
  { stage: 'layout',        maxDurationMs: 4000, maxMemoryMB: 100, targetDurationMs: 2000 },
  { stage: 'preparation',   maxDurationMs: 1500, maxMemoryMB: 40, targetDurationMs: 1000 },
  { stage: 'rendering',     maxDurationMs: 3000, maxMemoryMB: 200, targetDurationMs: 3000 },
];
```

### 2. 自動リグレッション検出 🔵

**信頼性**: 🔵 *既存regression-detector.tsパターンより*

ベンチマーク結果をベースラインと比較し、10%以上の悪化をリグレッションとして検出する。

**実装ファイル**: `src/pipeline/performance-regression-detector.ts`（新規）

```typescript
interface RegressionResult {
  stage: string;
  baselineMs: number;
  actualMs: number;
  regressionPercent: number;
  isRegression: boolean;
  severity: 'none' | 'warning' | 'critical';
}
```

**実装ファイル**: `src/pipeline/parallel-benchmark.ts`（新規）

### 4. コスト効率メトリクス 🔵

## 単体テスト要件

### テストケース1: ベースライン比較が正確 🔵

**信頼性**: 🔵 *既存ベンチマークテストパターンより*

**Given**: transcription baseline: 8000ms, actual: 9500ms
**When**: compareWithBaseline()を呼び出し
**Then**: 18.75%悪化 → リグレッション検出

**テストファイル**: `tests/pipeline/performance-regression-detector.test.ts`

### テストケース2: リグレッション重大度分類 🔵

**Given**: 10%未満の悪化 → warning, 25%以上 → critical
**When**: classifyRegression()を呼び出し
**Then**: 正確なseverityが返されること

**Given**: sequential: 12000ms, parallel: 5000ms
**When**: calculateSpeedup()を呼び出し
**Then**: 2.4x高速化として算出されること

**Given**: $0.03/video, 2000 tokens/analysis
**When**: calculateCostEfficiency()を呼び出し
**Then**: 正確なコスト効率スコアが返されること

**Given**: 5ステージのベンチマーク結果
**When**: generateReport()を呼び出し
**Then**: 有効なJSON形式で全ステージ結果が含まれること

## 注意事項

- ベースライン値は実測値に基づき、10%のマージンを含めること
- ベンチマークテストはCI環境での実行安定性を考慮し、タイミング閾値に余裕を持たせること
- メモリ計測はprocess.memoryUsage()を使用し、Node.js環境でのみ実行すること
- 並列化効果測定はTASK-0143の実装に依存するため、TASK-0143完了後に実装すること

- SYSTEM_CONSTITUTIONの範囲内（パイプライン支援・品質監視モジュール）であること
