## タスク概要

直近 4 commit（5c373b72 / 0318ddfb / 3fbece7d / 4800ae75）はすべて「sibling RED-witness standard への引き上げ」系で同種。steering feedback はこれらを 1 commit / 3-4 file 単位に統合する方針を推奨している。本タスクは：

- 直近 4 commit の diff を再走査し、論理的単位（例: 「MM:SS formatter guard」「config-restore finiteness」「Edge sanitizer codegen」「scene-graph helper extract」）に再分類
- 既に push 済みの commit は rebase/squash せず、今後の commit 粒度ルールを AGENTS.md または docs/rule/kairo/commit-policy.md に明文化
- レビュー観点：「3-4 file / 1 commit」を上限目安とし、同一 guard 拡張が複数 file にまたがる場合は 1 commit に集約

```markdown
# Commit 粒度ポリシー

## 基本原則
- 1 commit = 1 論理的単位
- 1 commit = 3-4 file 上限（目安）
- real fix + test ペアは 1 commit に集約可
- production code 修正と guard 拡張は別 commit

## 直近 4 commit の retrospective
- 5c373b72: MM:SS formatter guard (single fix + test) → 1 commit 適切
- 0318ddfb: TC-299-03 mutation witness (guard-only) → 1 commit 適切
- 3fbece7d: Edge sanitizer codegen (refactor + tests) → 1 commit 適切
- 4800ae75: scene-graph helper extract (refactor + 4 site update) → 1 commit / 4 file 上限ギリギリ許容

## 今後のルール
- 同一 guard 拡張で複数 file にまたがる → 1 commit に集約
- production code + guard は別 commit
- helper 抽出 + docstring + test は 1 commit
```
