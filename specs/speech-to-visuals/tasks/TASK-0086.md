## 実装詳細

### 1. カバレッジ乖離原因の特定 🟡

**信頼性**: 🟡 *測定設定の差の可能性*

現在の状況:
- **overview.md 主張値**: 84.61% statements
- **coverage-summary.json 実測値**: 68.73% statements
- **差分**: 約16ポイント

可能性のある原因:
- Jest設定の `collectCoverageFrom` 対象範囲の違い
- テスト追加後のカバレッジ再測定なし
- Phase 11タスク完了時の測定条件の違い

**確認手順**:
1. `jest.config.cjs` の `collectCoverageFrom` 設定を確認
2. `npx jest --coverage --ci` を実行して最新カバレッジを取得
3. モジュール別カバレッジを確認

**実装ファイル**: `jest.config.cjs`, カバレッジ設定関連

### 2. 低カバレッジモジュールのテスト追加 🔵

**信頼性**: 🔵 *coverage-summary.json モジュール別データより*

対象モジュール（statements < 60%）:

```
coverage/coverage-summary.json から特定:
- streaming-transcriber.ts (3.1%)
- その他低カバレッジモジュール
```

アプローチ:
1. 全モジュールのカバレッジ一覧を取得
2. statements < 60% のモジュールをリストアップ
3. 各モジュールの公開関数・分岐を分析
4. テストケースを設計・実装

**実装ファイル**: `src/**/__tests__/*.test.ts`

### 3. カバレッジ目標到達の確認 🟡

**信頼性**: 🟡 *テスト追加による改善量の推定*

目標:
- **statements**: 75%以上（現在 68.73%）
- **lines**: 75%以上（現在 68.98%）
- **branches**: 60%以上（現在 55.94%）
- **functions**: 75%以上（現在 68.6%）

追加が必要な推定テスト数: ~200-300テストケース（低カバレッジモジュール対象）

**実装ファイル**: 複数テストファイル
