**要件**: [requirements.md](../requirements.md) REQ-358〜360 / **受け入れ基準**: [acceptance-criteria.md](../acceptance-criteria.md) TC-353（本タスクで追加）

## 背景

Phase 157〜162（REQ-347〜354）はメモリ欠損シグナル（`@stv/core/utils/memory-usage` が heap フィールドを省略 / 非有限 drift）を、HealthCheckService の 3 消費層それぞれに isFiniteMetric/typeof guard を個別配置して fail-loud 化した。steering 指示のとおり、これは一時的に正しいが同じ欠損シグナルの再発を防げない — **実証**: adaptive-quality-gates は `snapshot.system` を無ガードで読み、`null < 85` 強制変換で critical Memory Usage gate が silent PASS・`null.toFixed(2)` で `evaluateGates` が crash していた（TASK-0251 残存 obligation でもあった）。

## 設計

**source 側出力契約**: 唯一の境界 `src/monitoring/memory-backend.ts` を新設し、`MemoryBackendReading`（heapUsed/heapTotal/rss/external）の全フィールドを「**有限数 or 明示 null**」に固定。undefined・NaN・±Infinity は決して返さない（`finiteOrNull` マッパー）。null = 「runtime がメモリ API を露出しない / backend が非有限値を返した」、backend zero-fallback `{0,0}` は実測の有限値として保存（unavailable との区別）。派生（`heapUsagePercentOrNull` / `heapUsagePercentRoundedOrNull` / `mbRoundedOrNull`）も同契約に乗せ、canonical `heapUsagePercent`/`bytesToMb` 委譲を同ファイルに集中（canon guard の pin 先も移動）。

**契約検証の集約**: `tests/unit/monitoring/memory-backend-contract.test.ts`（10 tests）が契約を**1 箇所**で機械検証。消費側は個別有限性 guard ではなく `=== null` 分岐のみを書く（型 `number | null` が書かない選択肢を排除）。

### 消費側移行（全メモリ読み出しが境界経由）

| 消費側 | 変更 |
|--------|------|
| real-time-performance-monitor `getSnapshot()` | system メモリ派生 4 field（memoryUsageMB/Percent・heapUsedMB/heapTotalMB）を `number \| null` に。欠損はフィールド単位で null 伝播・非メモリ field 無影響（REQ-359） |
| adaptive-quality-gates | `currentValue?: number \| null`・extractor が null → gate **FAIL（METRIC UNAVAILABLE）**・adaptive baseline seeding は null を skip（REQ-360・TASK-0248 残存 obligation 解消） |
| health-check-service | checkMemoryHealth/checkLiveness は `readMemoryBackend()` + `=== null`（pin 済み unavailable message 維持）・rss/external は `?? Number.NaN` marker → 契約 null |
| main-pipeline | getHeapUsed に加え readMemoryBackend で null 明示（2 site） |
| load-balanced-executor | memoryPressure は null → safeMean 集約用 zero-fallback 0（ドキュメント済み・捏造 ratio ではない） |
| performance-dashboard | **唯一の例外**: Phase 145 pin の NaN 伝播契約を維持 — null→NaN 写像をこの境界で明示 |

**集約の正直さ**: `isFiniteMetric` は廃止しない — `isFiniteMetric(null) === false` なので null は既存 guard を通り従来どおり unavailable 経路に入る（defense-in-depth + 契約外 NaN の保険）。生成系 derive は契約に任せ、消費側再検証をやめる、が本タスクの線引き。
