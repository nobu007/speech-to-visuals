**src/transcription 17 件 → 0 件**（2 ファイル・挙動保存置換 5 パターン）:

1. **`sanitizeFinite` 委譲**（5 サイト）: `Number.isFinite(v!) ? v! : k` → `sanitizeFinite(v, k)`。`@stv/core/utils/guards` の実装は `typeof value === 'number' && Number.isFinite(value) ? value : defaultValue` であり、`Number.isFinite` と値選択述語が完全一致（非 number は両述語とも fallback）して完全同値。対象: streaming-transcriber chunkAvgConfidence（chunk 品質監視）・mergeOverlappingSegments の平均・calculateAverageConfidence・whisper-transcriber validateAndEnhanceSegments（`sanitizeFinite(segment.confidence, 0.8)`）・logTranscriptionMetrics
2. **`?? Number.NaN` しきい値比較**: confidence フィルタ `segment.confidence! >= (minConfidence ?? 0.7)` → `(segment.confidence ?? Number.NaN) >= …`。旧 `!` は `undefined >= x` = false（=除外）・NaN も除外・Infinity は受理。`?? NaN` はこの全状態を保存。**0 fallback は非等価**: `minConfidence: 0`（合法値・accept-all）で undefined confidence が 0 >= 0 で受理され挙動が変わる（minConfidence と対称の falsy-legit-0 クラス・ファイル内コメントと同じ根拠）
3. **const capture**: live 配信（startLiveTranscription onresult）の segment.confidence — literal の property は optional 型に拡大されるため読み戻し比較に `!` が必要だった問題を、直前計算値 `const segmentConfidence = Number.isFinite(confidence) && confidence > 0 ? confidence : 0.8;` を literal と比較の両方に使う構造で解消（Phase 142 pipeline-orchestrator と同型）
4. **ctor 同型 `!== undefined` guard**: updateConfig の検証 4 検査。旧 `candidate.chunkSizeMs! <= 0 || …` は undefined で `undefined <= 0` = false が**全検査 pass-through**する挙動（spread で明示的 undefined が入り得る）を保存しつつ、constructor 自身の検証形（`if (config.x !== undefined)`）と同一の guard 形に統一。cross-field 検査（overlapMs >= chunkSizeMs）は両方 defined の場合のみ比較（旧 `undefined >= undefined` = false と同一）
5. **dead assertion 除去**: whisper-transcriber `id: segment.id! ?? index` → `id: segment.id ?? index`。`!` の直後の `??` が undefined を処理するため assertion は型検査を黙らせるだけで意味を持たない
