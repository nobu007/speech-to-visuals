### hit の実態（修正前 RED 実測: 5 failed / 60 passed）

1. **REQ-352 — `generateRecommendations` memory ゲート**: `metrics.system.memoryUsagePercent > 85` は omit / non-finite で FALSE 化し、"CRITICAL: Memory usage is very high" escalation が「高くない」と **区別不可能なまま silently suppress** される（偽 verdict の対極 = 偽 calm）。到達経路は REQ-347 が documented した browser-path memory 欠損と同一で、snapshot 経路では `getSnapshot()` の `roundTo(heapUsagePercent(undefined, undefined), 2)` = NaN（stv-core 実測で NaN 素通しを確認）。
2. **REQ-353 — `generateRecommendations` pipeline ゲート**: `metrics.pipeline.activeRequests > 10` も同一の FALSE 化パターンで horizontal-scaling 推奨が silent suppress。
3. **REQ-354 — `checkLiveness` の fabricated dead verdict**: `alive = latency < 1000 && memoryUsage.heapUsed > 0` の連言で、heapUsed の omit / non-finite（同一 browser-path 欠損）時に `undefined > 0` が FALSE 化し、**実測 latency が正常でも alive=false**。reason は常に latency を名指しするため実際の原因（memory metric 欠損）を偽って隠す — `src/api/routes/health.ts:48` の GET /health/live 消費者では restart 誘発。

## 修正

`src/monitoring/health-check-service.ts`（3 サイト・Phase 160 抽出の `isFiniteMetric` 述語を再利用）:

1. memory 推奨ゲート → `if (isFiniteMetric(metrics.system.memoryUsagePercent)) { … > 85 … } else { warn log + 'WARNING: Memory usage metric unavailable - criticality could not be assessed' }`
2. pipeline 推奨ゲート → 同型 + `'WARNING: Active-request count unavailable - scaling headroom could not be assessed'`
3. `checkLiveness` → `memoryMetricAvailable = typeof heapUsed === 'number' && Number.isFinite(heapUsed)` を導入し `alive = latency < 1000 && (!memoryMetricAvailable || heapUsed > 0)`。unavailable 時は sanity check を skip（latency が responsiveness signal のまま）し reason に `'memory metric unavailable: backend omitted/non-finite heapUsed'` を明示。not-alive reason も原因別に誠実化（latency 超過時のみ latency reason・`heapUsed ≤ 0` 時は Memory sanity check failed）。
