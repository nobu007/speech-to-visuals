## 背景

`src/quality/quality-monitor.ts` `evaluateIterationQuality`（`assessPipelineQuality` → Iteration Quality Score 5 leg 構成）の 3 leg が実測性を欠いていた:

| leg | 旧実装 | 実欠陥 |
|---|---|---|
| processingTime | `result.metrics?.totalProcessingTime`（optional extended copy）読み・未設定時 0.5 | MainPipeline の `PipelineResult.metrics` は `totalRetryAttempts` のみ populated（src/pipeline/main-pipeline.ts:567/:1095）で `totalProcessingTime` は**未生産**。常に 0.5 fallback になり、必須 field `result.processingTime`（types.ts で required・常に set）に実測があるのに無視 — wrong-field-in-parallel-pipelines class |
| memoryUsage | `result.metrics?.memoryUsage` 未設定時 0.5 | `ExtendedPipelineMetrics.memoryUsage`（bytes 契約・types.ts:81 doc）は optional で MainPipeline は未生産。未計測 0.5 が (1) 本 run の Iteration Quality Score 上限を 90% に固定 (2) `qualityScore < 0.9` 経由で**誰も測っていない metric への「💾 Implement memory optimization strategies」推奨**を恒久的に発生 — REQ-375「未計測 0 が完全レイアウトを主張」の対称形（未計測 mid が問題を主張） |
| documentation | `documentation: 1.0 // Assuming proper documentation` | 根拠ゼロの always-pass 定数が平均の分母を膨らませ実 leg の重みを希釈 — Phase 172「捏造 metric 委譲」と同型の残留 |

## 修正（src/quality/quality-monitor.ts）

1. **processingTime leg → `result.processingTime`（必須 field）を読む**。finite guard は維持（非有限時は低速側 score 0.5）
2. **memoryUsage leg → 計測時（finite number）のみ keyset に含める**。未計測は keyset から除外（keyset-derived denominator が既存 `averageCompliance` と同じ規則で分母を縮める）+ 💾 推奨は `memoryUsageMeasured &&` で gate。bytes 契約・256MB 閾値は不変
3. **documentation leg 除去**（捏造 constant の削除のみ・代替 estimator なし）

## テスト（src/quality/__tests__/quality-monitor.test.ts に 5 tests 追加）

1. production-shape（`metrics: { totalRetryAttempts: 0 }`）clean run → `Iteration Quality Score: 100.0%` + 💾 推奨なし
2. `metrics.totalProcessingTime: 99999` vs `result.processingTime: 10000` の不一致 → 必須側が権威（100.0%・🚀 なし）
3. `stages: []`（errorHandling 0）→ measured legs のみ平均 (1+0+1)/3 = **66.7%**（documentation leg 再追加で 75.0% に希釈されるのを pin）
4. 計測 512MB bytes → 💾 推奨あり（bytes 契約・閾値 pin）
5. 計測 NaN → 除外（scored にならない）
