## 背景

Phase 174 が QualityMonitor（0-100 scale）で閉じた「DEFAULT 0 が eq-0 zero-tolerance gate を無測定で恒久 GREEN にする」class（REQ-364 と同型）の隣接地を audit:
- (a) `performHealthCheck` の catch fallback（line 142-150）は `pipeline.successRate/avgProcessingTime`、`llm.cacheHitRate`、`errors.errorRate/recoverySuccessRate` の 5 field に **fabricated `0`** を返していた。`successRate > 0.95 healthy / cacheHitRate > 0.4 healthy / errorRate < WARNING && recoveryRate > 0.80 healthy` の各 gate を **fabricated verdict**（healthy = 100% success rate / 100% cache hit rate / 0% error rate）に routing、REQ-368 で閉じた memory/quality/llm-timing と同型。
- (b) `checkCacheHealth` の `const hitRate = totalHits / (totalHits + totalMisses) || 0;` は `0/0 → NaN` → `|| 0` で 0% を返し、`unhealthy "Cache is ineffective (0% hit rate)"` を emit。Phase 174 layoutOverlap DEFAULT 0 と同型（`isFiniteMetric` ガードは finite 入力のみ catch するため `0/0 NaN` は素通り）。
- (c) `activeRequests` についても `checkPipelineHealth` 内で `details` 行 surface 経由の gate-feeder として機能するため同 catch fallback 内に追加（REQ-378 履行範囲拡張）。

## 修正

### REQ-378 (a): catch fallback の gate-fed 6 field を null 化

`src/monitoring/health-check-service.ts` の catch fallback（line 142-150）を **`number | null` 明示 null** に変換:

```ts
pipeline: {
  successRate: null,        // fabricated 0 → 100% success rate routing を遮断
  avgProcessingTime: null,  // fabricated 0 → "instant" verdict を遮断
  activeRequests: null,     // gate-feeder 拡大で同 null 化
},
llm: {
  cacheHitRate: null,       // fabricated 0 → 0% cache hit routing を遮断
},
errors: {
  errorRate: null,          // fabricated 0 → 0% error rate routing を遮断
  recoverySuccessRate: null,
},
```

**counters / display accumulators without a gate（`totalRequests`・`totalErrors`・`p95/p99ProcessingTime`・`cpuUsagePercent`・`flash/proUsagePercent`・`estimatedCostSavings`・`uptime`）は 0 を保持**（"nothing recorded yet" は honest value）。

### REQ-378 (b): checkCacheHealth `|| 0` 置換

`hitRate = totalHits / (totalHits + totalMisses) || 0` → **`totalHits + totalMisses === 0` で degraded "no events recorded yet" 早期 return**:

```ts
if (totalHits + totalMisses === 0) {
  return {
    status: 'degraded',
    message: 'Cache monitoring unavailable: no events recorded yet',
  };
}
```

0/0 NaN → `|| 0` 復帰経路を完全消滅（`isFiniteMetric(hitRate)` ガードは維持）。

### REQ-378 (c): PerformanceSnapshot 型 widen + JSDoc 根拠明示

`src/monitoring/real-time-performance-monitor.ts` の `PerformanceSnapshot` interface で 6 field を `number | null` に widen。JSDoc に REQ-378 contract 根拠を明記（counter と gate-fed の distinction）。`activeRequests` の `isFiniteMetric` ガード追加で null 流入を遮断。

### REQ-378 (未履行・次サイクル): regression-detector.ts:298 silent skip

`if (baselineValue === 0) continue;` は design-heavy（`percentChange` canonical formula の `baseline===0 → 0` 戻り値と複合・意図設計）→ TASK-0262（REQ-378 残存 obligation）に送る。
