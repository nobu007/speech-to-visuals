## タスク概要

CPU集約処理をWeb Workersで並列化するための基盤インフラを構築する。Vite設定にWorker用ローダーを追加し、汎用的なWorker管理クラス（WorkerPool）とメッセージ型定義を実装する。これにより後続タスクでエクスポートエンジンやレイアウトエンジンの処理をWorker化できるようになる。

## 主要実装項目

### 1. Worker間メッセージ型定義 🔵

**信頼性**: 🔵 *architecture.md のレイヤー構成と既存TypeScriptパターンより*

`src/workers/types.ts` にWorker間通信のメッセージ型を定義する。

- `WorkerMessage<T>`: Workerへのリクエスト型（id, type, payload）
- `WorkerResponse<T>`: Workerからのレスポンス型（id, type, payload, error?）
- `WorkerMessageType`: メッセージ種別のunion type（EXPORT_RENDER, LAYOUT_COMPUTE等）
- `WorkerError`: Worker内エラー型（code, message, stack?）

**実装ファイル**: `src/workers/types.ts`

### 2. WorkerPool クラス実装 🔵

**信頼性**: 🔵 *architecture.md スケーラビリティセクションに明記*

`src/workers/worker-pool.ts` に汎用WorkerPoolクラスを実装する。

- コンストラクタでWorker URLと最大worker数を受け取る
- `execute<T>(message: WorkerMessage): Promise<WorkerResponse<T>>` メソッド
- アイドルWorkerの再利用（プールパターン）
- worker数上限到達時のキューイング
- Worker異常終了時の自動再生成
- `terminate()` で全Workerのクリーンアップ

**実装ファイル**: `src/workers/worker-pool.ts`

### 3. Vite Worker設定追加 🟡

**信頼性**: 🟡 *Vite公式ドキュメントの標準パターンより推測*

`vite.config.ts` にWorker用設定を追加する。

- `worker: { format: 'es' }` を設定
- `build.rollupOptions.input` にWorker用エントリーポイントは不要（動的import対応）
- 開発環境と本番環境の両方でWorkerが正しく動作するよう設定

**実装ファイル**: `vite.config.ts`

### 4. 既存コードのWorker対応準備 🔵

**信頼性**: 🔵 *既存コードの `workerPool: []` および `useWebWorkers: false` 設定より*

以下の既存ファイルのWorker関連フィールドを更新準備する：

- `src/export/enhanced-export-engine.ts` の `workerPool: Worker[]` をWorkerPool型に変更可能に
- `src/visualization/complex-layout-engine.ts` の `useWebWorkers: false` をトグル可能に

※実際の統合はTASK-0115で実施。本タスクでは型定義とインターフェースの準備のみ。

**実装ファイル**: `src/workers/index.ts`

## 注意事項

- ViteのWorkerサポートは `new Worker(new URL('./worker.ts', import.meta.url), { type: 'module' })` 構文を使用する
- テスト環境（Vitest）ではWorkerをモックする必要がある
- ブラウザ環境でのみWorkerが利用可能（SSR環境ではフォールバックが必要）
- 既存の `workerPool: []` フィールドはTASK-0115で実際に利用される
