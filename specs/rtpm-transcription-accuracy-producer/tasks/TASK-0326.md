## 実装詳細

### 1. real-time-performance-monitor.ts — report 拡張・ingestion・derivation 🔵

**信頼性**: 🔵 *architecture.md「コンポーネント構成」SD1〜SD3（現行 :211-216・:597-604・:710-720・:743-746・:909 の行番号実測付き）より*

**実装ファイル**: `src/monitoring/real-time-performance-monitor.ts`

- `PipelineQualityReport`（:211-216）に optional field `transcriptionAccuracy?: number | null` を追加（省略 = null）
- `recordPipelineQuality(measuredScenes: number, layoutOverlapCount: number, transcriptionAccuracy?: number | null): void`（:597）— 第 3 値は `typeof value === 'number' && Number.isFinite(value)` のときのみその値、それ以外（`undefined` / `null` / NaN / ±Infinity）は明示 `null` として report object へ（SD2・memory-backend.ts:51 `finiteOrNull` と同型）。`sanitizeFinite`（fail-loud fallback 0）は不採用 — 0 は estimator の実測 fail 値（失敗 run → 0・quality-estimators.ts:86）と区別がつかないため
- 新設 private `measuredTranscriptionAccuracy(): number | null` — 最新 report の第 3 field が finite number ならその値、report なし / field なしなら `null`（SD3）。REQ-372 の `measuredScenes > 0` gate は適用しない（accuracy の測定基盤は recovery chain 終端状態と run 成功形であり scene 数に依存しない — 0-scene 成功 run の 0.50 は実測 reading で gte 0.85 gate を loud fail させる）
- `getSnapshot().quality.transcriptionAccuracy`（:718 の無条件 `null`）を `this.measuredTranscriptionAccuracy()` に置換。`measuredLayoutOverlapCount()`（REQ-372 derivation・:743-746）と同型の構造に並べる
- field doc（:163-168）: transcriptionAccuracy の REQ-368 除外根拠（「estimator proxy の 0.90 は 0.85 blocker threshold を常に上回る」）は REQ-430 減点導入で消滅済みのため、0.90 / 0.5 / 0 が閾値両側に分布する弁別根拠に書き換え。`avgSceneQuality` の producer-less 継続根拠は残す。:710-717 の「the other two stay null」系コメントも「avgSceneQuality stays null」へ同期
- `reset()`（:909）は report object の clear で第 3 field も同時消去（追加変更なし）
