## タスク概要

`npm run pipeline:test:audio` の指す先は変えず、`scripts/test-complete-audio-pipeline.ts` 本体を測定経路に実質化する。現行は (a) 入力が hardcoded `public/jfk.wav` (b) 出力が console の timing breakdown のみ (c) WER・RTF・音声長を一切測定しない (d) exit が `qualityScore >= 70` heuristic（placeholder 経路でも green になり得る — 実装 line 353 `result.success = qualityScore >= 70`）で gate されている。これを corpus 駆動・WER/CER/RTF 実測・`stv-real-audio-e2e/1` JSON report・fail-loud exit に置換する。

## 主要実装項目

### 1. pure core と CLI 層の分離（D-2/D-3 と同一 harness 形式）🔵

**信頼性**: 🔵 *architecture.md「アーキテクチャパターン」節より*

**実装ファイル**: `scripts/test-complete-audio-pipeline.ts`（script 内に pure core を co-locate、又は `scripts/lib/` 等への切り出し — D-2 の「script に pure core を持たせる」形式に従う）

- pure core: argv 解析 / per-file 測定行（`FileMeasurement` + stage timings + rtf）組立 / report 組立（`buildReport` 相当）— timestamp・I/O 無し・決定論的
- CLI 層のみが `generatedAt`（ISO timestamp）と file I/O（`readFileSync`・stdout / `--output` 書き出し）を付与
- `inferenceRan` 判定は D-2 と同一規則（`success === true && segments.length > 0 && placeholder !== true && fallback !== true`）を pipeline result から導出する helper 1 箇所に集約

### 2. corpus 駆動 + full pipeline 実行 🔵

**信頼性**: 🔵 *dataflow.md 機能1 sequence・現行 script の stage 実装より*

- `discoverCorpus(filenames, references)`（D-2 import）で `public/audio` を走査。pair ごとに `simplePipeline.process({ audioFile, options: { includeVideoGeneration: false, useEnhancedLayout: false, layoutQuality: 'enhanced' } })` を現行と同じ options で実行
- 音声長は `readFileSync` bytes → `readWavDurationMs`（TASK-0314）。WAV 破損で throw した file は skipped（reason 付き）で続行 — 全 file skipped なら real run 0 件として fail-loud (b) に合流 🟡
- 動作は同期逐次（測定再現性のため並列化しない）。`performance.now()` による stage timing は現行実装を踏襲

### 3. WER/CER・集計の委譲（TC-406-03・duplicate-formula 回避）🔵

**信頼性**: 🔵 *REQ-422 (b)・設計決定 D3 より*

- hypothesis = `SimplePipelineResult.transcript`（`transcript?: string` は optional ので空時のみ segments join fallback 🟡 — 常在性を実装時に確認）
- reference = `<name>.txt` を UTF-8 で読んだ素のテキスト
- `normalizeText` → `computeWer` / `computeCer` を D-2 から import のみ。**script 内に Levenshtein・tokenize 等の第二実装を書かない**
- 集計行は `FileMeasurement` を構築して `summarize` に渡す。WER null（reference 空）は D-2 仕様の「測定不能」として summary の null 集計で残す（run 全体の失敗ではない）

### 4. report schema `stv-real-audio-e2e/1` 🔵

**信頼性**: 🔵 *architecture.md 手順4・設計決定 D2（RTF と総処理時間の分離）より*

```
{ schema: 'stv-real-audio-e2e/1', generatedAt, corpusDir,
  files: [{ name, language, audioDurationMs, transcriptEndMs, reference: { file, provenance },
            wer, cer, inferenceRan, placeholder,
            transcriptionRtf, totalProcessingMs, stages: [{ name, durationMs, success }], videoRender }],
  summary: { ...summarize の出典 + filesProcessed, realRuns, placeholderRuns, skipped[] } }
```

- `transcriptionRtf` = transcription 段の processingTime ÷ `audioDurationMs`（無次元。§3.1 Processing Speed の実測値になる）
- `totalProcessingMs` = E2E 全 stage 合計（分析・layout・render を含む — RTF と混ぜない）
- `transcriptEndMs`（最終 segment の end）を交差検証 field として併記（header 由来 duration との大幅乖離は警告であって失敗ではない）

### 5. fail-loud gate（`qualityScore >= 70` の廃止）🔵

**信頼性**: 🔵 *REQ-422 (a)・設計決定 D4・D-2 exit 1 契約（scripts/measure-transcription-accuracy.ts:406-411）より*

- Stage 6 Quality Assessment の heuristic 加算（`qualityScore` 合計 100 満点・line 310-342）と `result.success = qualityScore >= 70`（line 353）を削除し、上記完了条件の 4 分岐で exit を決める
- stderr メッセージは D-2 と同一契約（「placeholder run is NOT a measurement」系文言）— placeholder 経路・合成音・gate 閉が静かな偽測定として green になる経路を残さない
- video render 失敗は report 記録のみで exit に影響しない（現行の非 fatal 方針を維持）

**テストファイル**: `tests/scripts/test-complete-audio-pipeline.test.ts`

- **report 構造 leg**（TC-406-01）: pure core に合成測定行を与えて組んだ report が schema string・必須 field（`transcriptionRtf` / `totalProcessingMs` / stage timings / WER・CER / 参照出典）を持ち、実測 field がすべて有限であること

### mutation witness 🔵
