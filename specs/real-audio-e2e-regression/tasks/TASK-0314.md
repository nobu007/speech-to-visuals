## 主要実装項目

### 1. `parseWavHeader` + `readWavDurationMs` の新設 🔵

**信頼性**: 🔵 *architecture.md「音声長導出 helper」節・RIFF 仕様より*

`src/transcription/wav-duration.ts` に以下を export する:

- `parseWavHeader(bytes: Uint8Array): { audioFormat: number; channels: number; sampleRate: number; byteRate: number; bitsPerSample: number; dataChunkSize: number }` — RIFF chunk walk（`RIFF`/`WAVE` magic 検証 → chunk directory を順に読み `fmt ` の各 field と `data` の size を取得。chunk 順序に依存しない walk にする）
- `readWavDurationMs(bytes: Uint8Array): number` — `dataChunkSize / byteRate × 1000` を返す。両関数とも非 PCM（`audioFormat !== 1`）・magic 欠損・chunk 欠損・size 不整合は `throw`（fail-loud。呼び出し側は file を skipped 扱いにできる）

**実装ファイル**: `src/transcription/wav-duration.ts`

```typescript
/** WAV header 由来の音声長導出（pure — fs に触れないため合成 bytes で test 可能）。戻り値はすべて ms。 */
export interface WavHeader { audioFormat: number; channels: number; sampleRate: number; byteRate: number; bitsPerSample: number; dataChunkSize: number }
export function parseWavHeader(bytes: Uint8Array): WavHeader { /* RIFF chunk walk — 非 PCM / magic 欠損 / chunk 欠損は throw */ }
export function readWavDurationMs(bytes: Uint8Array): number { /* dataChunkSize / byteRate * 1000 */ }
```

## 基本的なテスト要件

### 手計算 pin（合成 bytes）🔵

**信頼性**: 🔵 *jfk.wav 実測（352,078 byte・16kHz mono 16bit → byteRate 32,000）の交叉検証より*

**テストファイル**: `tests/transcription/wav-duration.test.ts`

- 16kHz mono 16bit（byteRate = 32,000）・dataChunkSize = 320,000 → `10,000` ms の手計算 pin
- 44.1kHz stereo 16bit（byteRate = 176,400）の別構成 pin — channel 数が byteRate 経由で正しく反映されることの witness
- `audioFormat: 3`（IEEE float）→ throw・`RIFF` magic 破損 → throw・`data` chunk 欠損 → throw・chunk size が bytes 長を超過 → throw
- `fmt ` と `data` の前後順を入れ替えた bytes でも同一結果（chunk walk が順序非依存）
- doc comment に「戻り値は ms」があることの pin（単位契約）
