## 設計決定

1. **pin 前棄却を記録に残す** — `with` / `arguments.callee` を kind に
   しなかった理由（tsc strict の SyntaxError = 常時 CI FAIL・teeth 重複）
   を requirements と guard header の両方に明記。将来の候補選定の前例。
2. **ALLOWED は unify 不能の実測根拠付き** — structuredClone の jest vm
   欠落を実 probe で示し、「直せるが直すと test が壊れる」判断を cache
   しない。interface に non-JSON field が加わる変更は stale-row/negative
   anchor の二段で RED になり、同一 commit での再判断を強制する。
3. **empty-catch は単行 shape に限定** — `catch (e) {` の `}` が後続行の
   形式は行 detector の死角（現存 0 件を detector + `grep -A1` で確認）。
   ceiling は REQ-411-004 と guard header に明記（誤完全性の防止）。
4. **escape-unescape の detector は `(?:un)?escape`** — `un?escape` は
   `unescape`/`uescape` にしか match せず `escape` 単体を検出しない
   （liveness fixture 作成時に発見・修正済み）。fixture が正規表現の
   読み間違いを機械的に摘出した好例。
