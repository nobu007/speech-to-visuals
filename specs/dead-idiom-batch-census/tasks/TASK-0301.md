## 設計決定

1. **roster は guard 喪失を免除しない** — for-in の ALLOWED 行は「body が
   own-key filter を持つ as-is の site」への判定。filter を削除した site は
   roster に載っていても RED（MW-074 mutation (c) が実証）。ALLOWED を
   恒久免除にしないための 2 層構造。
2. **nullish 除外は行粒度**（同一行に `== null` と非 nullish `==` の混在は
   行ごと skip）— ceiling として REQ-410-008 に明記。行分割された idiom は
   AST pass 待ち（現存 0 件）。
3. **core 側 site は修正しない** — `@stv/core` は package 所有（in-tree
   修正不可）。ALLOWED の CORE-TYPED 理由で typed-param 等価性を明記し、
   core 側 CI へ移譲。
4. **batch 形式**（1 phase / 1 TASK / spec 5 file）— steering 契約の最初の
   実装例。次 family から zero class は本 guard へ kind 追加のみで参加可能。
