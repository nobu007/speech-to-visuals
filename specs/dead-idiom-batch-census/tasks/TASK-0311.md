## 背景

MW-083 採用時の LLM 評価で、`/\.filter\(.*\)\s*\[\s*0\s*\]/` の greedy `.*` 脆性が指摘された:

> `filter-index-zero` の regex `/\.filter\(.*\)\s*\[\s*0\s*\]/` は greedy `.*` のため `xs.filter(f); const a = other[0];` のような同一行別式で誤検出しうる（fixture では未検証）

PINNED guard は fail-closed が基本姿勢（誤検出は正当な CI を恒常 RED 化させる）であり、fail-open 側（見逃し）のリスク受容が好ましい。

## 実施内容

1. **detector balanced-arg 化**: `/\.filter\(.*\)\s*\[\s*0\s*\]/` →
   `/\.filter\((?:[^()]|\([^()]*\))*\)\s*\[\s*0\s*\]/`（引数 span を
   `[^()]` フラット + `\([^()]*\)` 1 段ネストで表現。2 段ネストは blind spot 受容）
2. **fixture (ad1b)**: sibling-statement 形
