## 設計決定

1. **3 site の ALLOWED は文脈を実証** — detector は行テキストしか見られ
   ないため、(a) logger :20 の level gate が隣接行にあること、(b)
   api/index :64 が「全 service 停止 log の後」の gracefulShutdown
   epilogue であること、(c) guards :114 が typeof+Number.isFinite gate 内
   の有限数 branch であること、を read で確認し negative anchor で文脈
   共存を pin。teeth は生存（MW-078 (c) で stale-row/floor 双方向を実証）。
2. **charCodeAt の投資不釣合型棄却は Math.max(...xs) 前例の踏襲** —
   15 site 全てが code-unit-domain 正利用（kana BMP・ASCII byte・Latin-1・
   security compare）であることを read で確認した上で per-site prose の
   投資を回避。astral-plane text math site 出現時の再計測を guard header
   に明示的に定義。
3. **assignment-in-condition の検出不可能型棄却** — 計測 15 hit 全てが
   arrow `=>` か正典 `while ((m = re.exec(src)))` loop で、行 regex には
   区別不能。REQ-413 の `.map(async` と同じ「消費側/構文脈で可否が決まる」
   class として記録。
