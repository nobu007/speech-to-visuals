## 設計決定

1. **Math.pow の pin 前棄却** — `a ** b` と挙動完全一致（負底の小数指数
   は両方 NaN・deopt も同じ）。13 実測 site は backoff/exponent 計算の
   正当利用で incident shape がゼロ。REQ-411-003（tsc 重複棄却）と
   並ぶ「棄却にも根拠を残す」系列の 2 例目 — 将来の候補選定前例。
2. **`>>> 0` は class 外 scoping** — CRC32（apng-encoder）と mulberry32
   （layout-rng）は unsigned coercion を**要求**する。bitwise-truncation
   kind を `~~` / `| 0` に絞ることで正当 bit 演算の false-positive を
   回避（detector 設計時点で実測 site の全数を読んで scoping）。
3. **byte-domain ALLOWED は引数域を実コードで確認** — fromCharCode 5 site
   すべて引数が 0..255 に bounded することを read で確認
   （Uint8Array 要素読み・`count < 255` loop guard）。「たぶん大丈夫」で
   なく根拠を roster 理由文に記録。
4. **unify の count 検証** — 5 site の部分 regress（4/5 revert）は
   anchor 1 件では捕捉できないため、`parseInt(e.target.value, 10)` の
   出現数 = 5 の count 検証を同梱（MW-076 (b) で 3 独立 leg を実測）。
