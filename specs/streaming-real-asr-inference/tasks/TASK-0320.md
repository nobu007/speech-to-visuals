## タスク概要

TASK-0319 の routing 改修で流れてくる segments には「未測定（`confidence: undefined` — whisper.cpp 由来）」と「実測値 / 開示 standin（数値）」が混在する。現行実装は (1) minConfidence filter が `(segment.confidence ?? Number.NaN) >= threshold`（streaming-transcriber.ts:178-179）で**未測定を常に reject** するため実経路の結果が全滅する (2) `StreamingQualityMonitor.evaluateChunk`（streaming-quality-monitor.ts:129-131）が非有限値を 0 に変換して reject 計上するため**未測定 chunk が捏造 0-reject になる**。この 2 点を「未測定は通過・評価は実測値のみ」へ書き換える。

## 主要実装項目

### 1. filter の未測定通過 🔵

**信頼性**: 🔵 *architecture.md confidence semantics 節（現行 comment 语义 :172-177 の更新条件まで記載）より*

`confidence` が `undefined` の segment は無条件通過。数値の場合のみ `>= (this.config.minConfidence ?? 0.7)` と比較。`minConfidence` 側の `??`（explicit 0 を受ける）は現行どおり維持。comment の「undefined は threshold 未満」语义は本書き換えで廃止 —「開示 placeholder segment には常に数値 confidence が付く」設計の下で成り立つ语义に置換する。

**実装ファイル**: `src/transcription/streaming-transcriber.ts`

```typescript
// 未測定（undefined — whisper.cpp 由来）は「低測定値」と区別され通過する。
// 数値（実測 or 開示 placeholder の 0.75 / standin 0.5）のみ閾値と比較する。
const validSegments = segments.filter(segment =>
  segment.confidence === undefined || segment.confidence >= (this.config.minConfidence ?? 0.7)
);
```

### 2. evaluateChunk の実測限定 wiring 🔵

**信頼性**: 🔵 *dataflow.md「品質 monitor / 言語検出への流入」（経路別の評価規則が明記）より*

- **経路1（Web Speech）**: utterance（final result）を評価単位とし、数値 confidence（実測 or `FINAL_NO_CONFIDENCE_STANDIN` — standin は standin 実測値として評価に含める・REQ-093 语义）を持つ utterance のみ `evaluateChunk(index, confidence)` を呼ぶ
- **経路2（whisper 委譲）**: segments が confidence を持たないため `evaluateChunk` を呼ばない。`getQualitySummary()` は評価対象 chunk なしの形状を返す
- **経路3（開示 placeholder）**: `qualitySummary` を evaluate しない（placeholder run は測定ではない — REQ-391 契約の進捗版）

**実装ファイル**: `src/transcription/streaming-transcriber.ts`（monitor 側は変更なし）
