## タスク概要

Web Speech による File 文字起こし mechanism（`URL.createObjectURL` + `Audio` 実時間再生 + `SpeechRecognition` の onresult/onend/onerror + `URL.revokeObjectURL`）を、**final result（utterance）が出るたびに callback を発火する**純粋 engine として `src/transcription/web-speech-file-transcription.ts` に抽出する。`BrowserTranscriber.transcribeWithWebSpeechAPI`（browser-transcriber.ts:324・private）は本 engine への委譲に置き換える。TASK-0319（routing 改修）の browser 分岐が消費する基盤であり、第二の file 再生 + recognition 実装を作らないための単一ソース化（duplicate-formula class の事前封じ）。

## 主要実装項目

### 1. engine `transcribeFileWithWebSpeech` の新設 🔵

**信頼性**: 🔵 *browser-transcriber.ts:324-391 の現行 mechanism（設計の抽出元として実在）より*

browser-transcriber.ts:324-391 の mechanism をほぼそのまま持つが、次の差分を持つ:

- **progressive callback**: `onresult` で `isFinal` result を処理するたびに `hooks.onFinalSegment(segment)` を発火（現行は segments 配列に蓄積するのみ）
- **空は空**: `onend` 時 `segments.length === 0` でも `getEnhancedMockSegments()` を返さず `[]` を resolve（現行 :382 の mock フォールバックは engine に持ち込まない）
- **`SpeechRecognition` 構築**: engine 内で `window.SpeechRecognition || window.webkitSpeechRecognition` から構築（BrowserTranscriber の `this.recognition` に依存しない — engine は StreamingTranscriber からも呼ばれるため単独で完結する）

- **timestamp 規約**: `start` = 直前の final result 到達時刻、`end` = `audio.currentTime * 1000`（現行 :344-356 と同一）
