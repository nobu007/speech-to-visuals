# Auto-Commit Remaining Changes

Commit all uncommitted changes in the current repository. This is designed for post-task cleanup.

## 1. Check Status

!`git status --short`

If there are no changes, report "No changes to commit" and exit.

## 2. Analyze Changes

!`git diff --stat && echo "---UNTRACKED---" && git ls-files --others --exclude-standard`

Group changes into logical commit units:

- Modified tracked files related to the same feature/fix → one commit
- New untracked files → separate commit if they're intentional project files
- Generated/temporary files (build artifacts, cache, logs) → do NOT commit, add to .gitignore if appropriate

## 3. Commit Loop

For each logical group:

1. Stage the files: `git add <files>`
2. Commit with a descriptive Conventional Commits message:
   - `feat:` for new features
   - `fix:` for bug fixes
   - `refactor:` for code restructuring
   - `chore:` for maintenance/config changes
   - `docs:` for documentation updates
   - `test:` for test additions/fixes

If all changes are closely related, a single commit is acceptable.

**Rules:**

- Do NOT commit binary blobs, media files, or large data files (>1MB) unless they are clearly part of the project
- Do NOT commit files that look like personal/local config (`.env`, IDE settings not in `.gitignore`)
- If unsure about a file, skip it

## 4. Final Status

!`git status`
Report what was committed and what was intentionally skipped.
